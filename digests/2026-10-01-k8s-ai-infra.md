# K8s AI 基础设施周报 2026-10-01

> 覆盖窗口:2026-09-24 ~ 2026-10-01。数据源:GitHub API(releases / merged PR / KEP)。

## 摘要(3 条以内)

1. **v1.38 周期开张,上游原生调度一次性放大招**:原生 gang 调度(KEP-4671)与 workload-aware preemption(KEP-5710)双双冲 **GA**;CompositePodGroup(KEP-6012)进 **beta**;WAS Controller API(KEP-6089)进 **beta** 并把可复用结构体直接提升进 `scheduling.k8s.io/v1`,已有 **7 个控制器**适配(JobSet / LWS / Kubeflow Trainer / Spark Operator / KubeRay + 核心 Deployment / StatefulSet)。"上游收编 gang"从路线图变成了既成事实。
2. **Workload API 开始渗入核心工作负载控制器**:KEP-6276(Deployment,in-tree)+ KEP-6277(StatefulSet,alpha)落地——连长运行副本服务都能原生 gang 调度,不再是批作业专属。这是对生态调度器"gang 独占性"最直接的稀释。
3. **DRA 在 v1.38 密集毕业**:Partitionable Devices(KEP-4815)、Consumable Capacity(KEP-6375)双双 **GA**;另有 4 个 DRA 子 KEP 进 beta/新增。同期 Kueue v0.20.0 发布,删除 v1beta1、大幅强化 DRA 设备可行性检查。device-plugin 时代进入倒计时。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

本周是这条主线自 v1.35 启动以来**进展最猛的一周**,v1.38 目标状态如下:

- **KEP-4671 Gang Scheduling → GA(v1.38)**。原生 gang 从 alpha(v1.35)用三个版本走到 GA,节奏快于预期。
  https://github.com/kubernetes/enhancements/pull/6349
- **KEP-5710 Workload Aware Preemption → GA(v1.38)**;配套澄清了 `PodGroupPreemptionPolicy` 毕业标准与优先级校验(#6420)。
  https://github.com/kubernetes/enhancements/pull/6367
- **KEP-6089 WAS Controller APIs → Beta(v1.38)**:把 `Workload` / `PodGroup` 的可复用构件直接提升进 `scheduling.k8s.io/v1`(因为要被 `batch/v1.JobSpec`、`apps/v1.DeploymentSpec` 内嵌),v1alpha3 用 Go type alias 保向后兼容。KEP 正文列出 **7 个适配控制器**:JobSet、LWS、Kubeflow Trainer、Spark Operator、KubeRay(out-of-tree)+ 核心 Deployment、StatefulSet(in-tree)。另新增 `workload-name` annotation(#6444)。
  https://github.com/kubernetes/enhancements/pull/6342
- **KEP-6012 CompositePodGroup API → Beta(v1.38)**:支持嵌套/组合的 PodGroup 层级。设计上做了收敛——移除了 `Permit` 相关改动(gang 插件里已删,见 k/k #141182),放弃非贪婪评估与有界回溯启发式。实现侧 k/k 本周多笔落地:KEP-6012 为 Composite Pod Groups 实现 status(#140670)、GC finalizer 保护(#141021)、`MinGroupCount` 可变(#141023)、`PodGroupProtectionController` 重构(#142387)、`PodGroupWrapper.WorkloadRef` 签名修正(#142378)。
  https://github.com/kubernetes/enhancements/pull/6348
- **KEP-6276 Workload API × Deployment controller(in-tree)**:让长运行副本服务支持 gang 调度。
  https://github.com/kubernetes/enhancements/pull/6295
- **KEP-6277 Workload API × StatefulSet(alpha,新增)**:有状态工作负载的原生 gang。
  https://github.com/kubernetes/enhancements/pull/6298

> **WAS 原生化 vs 生态调度器(常设研判)**
> 本周天平明显向上游倾斜。此前判断是"Kueue 已把 DRA/Workload 当默认路径追、Volcano 的 gang 独占性在被稀释",现在要升级:
> - **对 Volcano**:最直接的挤压。gang GA + Deployment/StatefulSet 原生 gang,意味着"为了 gang 而装 Volcano"的理由在标准发行版上被釜底抽薪。Volcano 的护城河要从"gang 本身"转向"批调度策略丰富度(fair-share/队列/回填/拓扑/异构卡编排)+ 昇腾等国产卡深度集成"——纯 gang 场景会被原生吃掉。
> - **对 Kueue**:整体利好。Kueue 定位在 gang/调度之上的"配额与准入",正好站在原生 PodGroup/Workload 之上;v0.20.0 的 `SchedulerLibraryIntegration`、`WorkloadAwareScheduler` 系列 gate 正是在往"复用上游 scheduler-library"方向走,属于顺势。
> - **对 KAI(NVIDIA)/第三方调度器**:与 Volcano 类似承压,但 7 个适配器里 KubeRay/Trainer 的 WAS 集成说明"推理/训练框架直接对接原生 Workload API"会成为新常态,绕过第三方调度器的 CRD。
> - **对我们产品**:架构选型应开始**以原生 Workload/PodGroup API 为默认 gang 底座**来设计,生态调度器退为"增强策略层/国产卡适配层"的可选插件,而非必选依赖。6 个月内 v1.38~v1.39 落地后,这会成为企业客户的默认预期。

### Kueue

- **v0.20.0 发布(2026-09-30)**,同日另发 v0.19.7 / v0.18.11 补丁。重大变更(升级前必读):
  https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.0
  - **API 破坏**:不再提供 `kueue.x-k8s.io/v1beta1`,升级前须用官方 `migrate-to-v1beta2.sh` 迁移存量对象(#14558)。
  - **DRA 大幅加强**:新增 `KueueDRADeviceFeasibility` gate(alpha)——准入前按节点校验设备可用性,避免为 kube-scheduler 放不下的 Workload 预留配额(#15577);叠加 ResourceSlice/DeviceTaintRule 污点校验(#16081、#16169);`adminAccess:true` 请求不计 DRA 配额(#13642);修复 Pod overhead/转换输出共享 DRA 资源名时的配额漏算(#14154)。
  - **TAS(拓扑感知)多项毕业**:`TASGroupedPodSetSlicing`、`TASNodeFeasibilityForAllLevels`、`TASCacheTopologyTree` 等转 beta 默认开;支持 LWS 组按 rack/zone 打散同时组内聚合(#14820)。
  - **LWS 集成修漏**:`spec.leaderWorkerTemplate.size` 在被 Kueue 托管期间变为不可变(新 gate `LWSImmutableGroupSize`,beta 默认开),堵住了调大 size 绕过配额的漏洞(#13279)。
  - 另:`WorkloadPriorityClassDefaulting`、`MultiKueueOrchestratedPreemption` 等转 beta;新增 alpha `ConfigurablePreemptions` PreemptionConfig API(#15913)。

> 启示:Kueue 把 DRA 可行性检查做进准入层,解决了"配额充足但设备放不下→Workload 永久 pending"这一真实痛点,对多租户 GPU 集群是刚需。我们若自建配额层,这套"准入前设备预检"的思路值得直接借鉴。

  https://github.com/kubernetes/enhancements/pull/6381

- **KEP-5491 DRA List Types for Attributes → beta**(#6354)

> 启示:Partitionable Devices + Consumable Capacity 同时 GA,意味着"一张物理卡按 partition/容量切给多个 Workload"这件事在 v1.38 有了**稳定的原生 API**。这正面冲击 HAMi/vGPU 这类"软件层切卡"方案的长期定位——它们要么往 DRA driver 形态收敛,要么退守 DRA 还没覆盖的国产卡/特殊共享模式。需持续跟踪 HAMi 的 DRA 适配路线。

## 值得跟进

- [ ] **把"原生 Workload/PodGroup gang"定为产品默认 gang 底座**:v1.38 GA 后,生态调度器应退为可选增强层。评估我们现有依赖 Volcano/Kueue gang 的组件,规划迁移到原生 PodGroup 的路径与时间线。
- [ ] **跟踪 KEP-6089 的 7 个适配控制器**:尤其 KubeRay / Kubeflow Trainer 的 WAS 集成 PR——这决定"推理/训练框架直接对接原生 Workload API"的成熟度,影响我们是否还需要在中间塞调度器 CRD。
- [ ] **DRA 切卡 GA 对 HAMi/vGPU 的冲击研判**:Partitionable Devices + Consumable Capacity 均 GA,确认 HAMi 的 DRA driver 适配路线图,评估"软件切卡"方案的长期替代风险(联动 hami-watch task)。
- [ ] **Kueue v0.20.0 升级评估**:v1beta1 移除是破坏性变更,若有组件依赖 Kueue API 需排期迁移 v1beta2;其"准入前 DRA 设备预检"思路可借鉴到自研配额层。
- [ ] **Volcano 护城河再定位**:gang 被原生收编后,持续观察 Volcano 是否把重心转向批调度策略丰富度 + 国产卡(昇腾)深度集成(联动 compute-ascend-watch / compute-nv-watch)。
- [ ] **LWS DisaggregatedSet vs grove**:PD 分离/多角色编排两条路线对比,下月扫一眼 ai-dynamo/grove release(本周仍停在 alpha.14-rc1)。
