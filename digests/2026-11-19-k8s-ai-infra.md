# K8s AI 基础设施周报 2026-11-19

> 窗口:2026-11-12 ~ 2026-11-19(v1.38 Code Freeze 11-17 当周)。上一期 k8s-ai-infra 是 2026-10-29,中间断了两周;10-29 ~ 11-11 之间没被覆盖的关键发版和 GA 单独放在文末「窗口外补记」。通用 K8s 能力(WatchList GA、IPPR 抢占 beta 等)见同日 `k8s-core`。

## 摘要(3 条以内)

1. **v1.38 冻结后 WAS 主线定型:内核原语不冲 GA,接入面继续扩到更多控制器。** KEP-4671 Gang/Workload 在 1.38 继续停在 beta,KEP-5710 workload-aware preemption 推迟 GA,原来的 `PodGroupPreemptionPolicy` gate 并入 `GenericWorkload`。同一周 KEP-5547 Job 集成升 beta(默认关),KEP-6276 把 Workload API 接进 Deployment/ReplicaSet(alpha,`.spec.scheduling` 支持 gang、拓扑约束和共享 ResourceClaim)。原生 gang 已经从「Job 专用」扩到「推理用的 Deployment 也能用」。
2. **DRA 在 1.38 一次进了一批「共享/分片」能力**:可消耗容量 KEP-5075 GA(11-04);新增 alpha 的共享可消耗容量 KEP-5941、DRA 扩展资源容量 KEP-6406 和 DRA 抢占框架 KEP-5690;KEP-5517 Node Allocatable、KEP-5491 列表属性、可选节点操作升 beta。GPU 分片和共享的上游标准路径基本铺齐了。
3. **生态侧已经在适配**:Kueue main 合入「同一 DeviceClass 按容量维度分别计配额」和 `excludeDeviceClassNames`;Volcano v1.15.4/v1.14.7 修复「只申请 DRA 资源的 Pod 绕过 gang」;Kthena v1.1.0 发布,支持外部模型 Provider 路由和会话粘性。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

**1.38 冻结后的定局:内核原语稳住在 beta,先扩接入面。**

- **KEP-4671 Gang/Workload API 1.38 继续停在 beta**(KEP 文档 PR #6494 于 11-16 合入)。https://github.com/kubernetes/enhancements/pull/6494
- **KEP-5710 workload-aware preemption 推迟 GA**,`PodGroupPreemptionPolicy` gate 合并进 `GenericWorkload`(#6491;对应 k/k #143266 于 11-04 删除了该 gate)。https://github.com/kubernetes/enhancements/pull/6491 、https://github.com/kubernetes/kubernetes/pull/143266
- **KEP-5547 Job 集成升 beta(默认仍关)**(#143188,`WorkloadWithJob`)。配套改动:Job suspend 时只删 PodGroup、保留 Workload,resume 时先建新 PodGroup 再建 Pod,按新 gang 重新调度(#143537);Job 上的委托注解 `scheduling.k8s.io/workload-name` / `group-template-name` / `parent-compositepodgroup` 创建后不可改(#143863);job-controller 补上删除 PodGroup 的 RBAC(#144221,回归修复)。
  - https://github.com/kubernetes/kubernetes/pull/143188
  - https://github.com/kubernetes/kubernetes/pull/143537
  - 对 Kueue 的意义:suspend/resume 是 Kueue 准入的核心机制。「suspend 删 PodGroup、resume 重建」说明上游已经按「外部队列控制 suspend + 原生 gang 负责落地」的分工在设计。
- **KEP-6276 Deployment/ReplicaSet 接入 Workload API(新 alpha,`WorkloadWithDeployment`)**:Deployment 的 `.spec.scheduling` 支持 gang、拓扑约束、disruption 模式和共享 ResourceClaim。https://github.com/kubernetes/kubernetes/pull/143235 、https://github.com/kubernetes/enhancements/issues/6276
- **PodGroup / CompositePodGroup 层级深度上限从 4 改为 5**(#144193,KEP-6012)。https://github.com/kubernetes/kubernetes/pull/144193
- 其余 v1.38 支撑项:异构 PodGroup/CompositePodGroup 调度和抢占的集成测试(#143832/#143834/#143836),调度器快照导出 PodGroup 内 Pod 的增删改(#144202),新增 first-fit 节点过滤选项 `WithFirstFit`(#143976)。https://github.com/kubernetes/kubernetes/pull/143976

> **WAS vs 生态调度器研判:这周对 Volcano 是中长期挤压,对 Kueue 是利好,对 KAI 影响中性偏压。**
> - **Volcano**:KEP-6276 让 Deployment 原生支持 gang 和拓扑约束。多副本推理(PD 分离、多机推理)以前要靠 Volcano PodGroup 或 LWS 的 gang,现在原生 Deployment 加一个字段就能表达。Volcano gang 的独占性从训练侧进一步稀释到推理侧。不过 4671/5710 都没冲 GA,1.38 周期内生产用户仍会观望,**Volcano 还有约 2 个版本(约 8 个月)窗口**,可以把差异化放到队列层级、配额回收和异构 worker(见下文 #6230)上。
> - **Kueue**:Job 集成 beta 的 suspend/resume 语义和 Kueue 的准入模型一致,Kueue「准入 + 配额,不自带调度器」的路线越来越顺。
> - **KAI**:它的核心价值是 GPU 拓扑和分片调度,和 DRA 共享容量(下节)正面重叠;gang 被原生化的影响与 Volcano 相同。
> - **对我们产品的启示**:1.38 GA 时,Deployment 原生 gang 还是 alpha,不建议产品直接依赖。但**推理编排层(我们的 ModelServing 类 CRD)应该预留「生成原生 Workload/PodGroup」的 backend 抽象**,不要把 Volcano PodGroup 写死。v1.39 / v1.40 一旦 4671 GA,可以无痛切换。

### Kueue

- **v0.20.6 / v0.19.13**(11-12),全部是 bug 修复,和 AI 集群相关的几条:
  - **升级 v0.20 后 kube-apiserver 反复初始化 watch cache 失败**:CRD 仍为未服务的 `v1beta1` 配置了 `/convert` webhook,而 manager 已不再提供该接口(#18411)。**从 v0.19 升级的用户必须打这个补丁**。
  - ElasticJobsViaWorkloadSlices:弹性扩容时 workload slice 和替换 slice 被重复计费,短时超配额(#18648)。
  - MultiKueue:worker 都没能预留配额时,准入检查消息会带上各 worker 的原因,比如 `DRAResourcesUnresolved`(#18605);worker 断连时首次提名的 Workload 不再永久 pending(#18428)。
  - TAS:同等容量的拓扑域打平时改为优先填充较小或部分占用的祖先域,不再按字母序,减少大块拓扑碎片化(`TASAncestorCapacityTieBreak` beta,默认开,#18537)。
  - https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.6
- **main 新功能(将进 v0.21)**:
  - **DRA:同一 DeviceClass 可按每个可消耗容量维度分别设配额**(#17642,11-17)。直接对应上游 KEP-5075 GA:一张卡的显存、算力等维度可以分别计配额,是 GPU 分片配额的关键能力。https://github.com/kubernetes-sigs/kueue/pull/17642
  - **DRA:`resources.excludeDeviceClassNames`**(alpha `KueueDRAExcludeDeviceClasses`,#18632):对列出的伴生设备类(如 NIC/RDMA 这类不需要计配额的设备)不计配额,也不因 `allocationMode: All` 或缺映射而拒绝。https://github.com/kubernetes-sigs/kueue/pull/18632
  - Deployment 运行中可修改 queue-name 和 priority class(#17575/#18287);LWS 在有效 requests 不变时允许改容器模板(#17903)。

### Volcano / Kthena

- **Volcano v1.15.4 / v1.14.7**(11-12)。和 AI 调度直接相关的修复:
  - **只申请 DRA 资源的 Pod 的 gang 判定修复**:之前这类 pending Pod 会被算进 gang 就绪,或通过 backfill 绕过 gang 约束(#6263/#6265)。说明 Volcano + DRA 组合仍在踩坑期。
  - 父队列容量校验计入子孙队列的 scheduling-gate 预留(#6072);Completed PodGroup 在 Pod 删除后不再重新占用队列配额(#6054);抢占时排除有不可解谓词失败的节点,避免无谓驱逐(#6125)。
  - https://github.com/volcano-sh/volcano/releases/tag/v1.15.4
- **Volcano main**:
  - **distributed-framework 插件(mpi/pytorch/tensorflow/hcclrank)支持多个 worker task**(#6230):一个 VCJob 可以混合不同 GPU 型号或机型组成同一个 MPI world。`hcclrank` 在列,昇腾异构训练也会用到。这正是原生 Workload API 暂时不覆盖的差异化点。https://github.com/volcano-sh/volcano/pull/6230
  - gangpreempt/gangreclaim 选 victim 时遵从 PDB(#6303)。https://github.com/volcano-sh/volcano/pull/6303
- **Kthena v1.1.0**(11-12,rc.0 为 11-02):
  - 路由侧:新增 `ExternalModelProvider` CRD(alpha),同一入口同时路由集群内模型和 OpenAI 兼容 / Anthropic 等第三方 API(凭据放 Secret,复用鉴权、限流和计量);会话粘性路由(PD 分离时粘到同一 P/D 对,存储可选 memory 或 Redis);内存版 KV cache 索引加独立 tokenizer 服务,不再依赖 Redis 和引擎侧分词;router 可脱离 K8s API server 独立运行。
  - ModelServing 侧:`maxSurge`、InPlace 镜像更新、Role 协调滚动、按 Role partition、驱逐保护 webhook。
  - **`ModelBooster` 废弃**,改用 ModelServing + ModelRoute + ModelServer。几项默认值有变化(router `/metrics` 端口、`recoveryPolicy: None` 语义),升级前要看 Upgrade Notes。
  - https://github.com/volcano-sh/kthena/releases/tag/v1.1.0
  - 启示:Kthena 正从「集群内推理路由」扩成「统一 LLM 网关」,和 KServe / Envoy AI Gateway 的赛道重叠变大。openFuyao 跟进 Kthena 的话,大概率会直接拿到外部模型路由能力。

### DRA

(重中之重。1.38 是 DRA「共享/分片」语义的集中落地版本。)
- **新 alpha**:
  - **KEP-5941 共享可消耗容量**(`DRASharedConsumableCapacity`,#140084):ResourceSlice counters 可以通过 `valueFrom` 建模「按请求驱动的共享计数器消耗」,调度器跨已有分配统计共享计数器。这是多个分片共享一块物理资源池(如显存、带宽)的上游表达。https://github.com/kubernetes/kubernetes/pull/140084

  - **KEP-5690 DRA 抢占:调度框架支持**(#144065)。https://github.com/kubernetes/kubernetes/pull/144065
  - KEP-5677 资源池状态请求 `ResourcePoolStatusRequest`:补齐 1.38 alpha 语义和指标(#143242)。
- **升 beta**:
  - **KEP-5517 DRA Node Allocatable**(#142768,1.38 默认关,`--min-compatibility-version>=1.38` 时默认开):**ACTION REQUIRED**,alpha 字段 `NodeAllocatableResourceClaimStatuses` 被 `ExtraNodeAllocatableResources` 取代,用过 alpha 的 Pod 升级后要重建。https://github.com/kubernetes/kubernetes/pull/142768
  - KEP-5491 列表类型属性 beta(#144150);可选节点操作 `DRAOptionalNodeOperations` beta、默认开(#143775,驱动可以跳过 NodePrepare/Unprepare)。https://github.com/kubernetes/kubernetes/pull/143775
- **分配器修复**:admin access 不再计入容量和计数器(#144073/#144115/#144119),pending 容量不再重复计数(#144198),Reserve 阶段 pending 与新分配结果串线修复(#144080)。https://github.com/kubernetes/kubernetes/pull/144080
