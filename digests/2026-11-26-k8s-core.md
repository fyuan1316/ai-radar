## 调度(kube-scheduler)

- **v1.37.3 / v1.36.7 修复 scheduler 崩溃**:同 namespace 下同名 Pod 被快速删除再重建时,scheduler 会 crash。用 Job/StatefulSet 频繁重建同名 Pod 的场景(训练任务重试)容易触发,建议升级。https://github.com/kubernetes/kubernetes/pull/144204
- **IPPR 调度侧修正(v1.38)**:scheduler 在评估 deferred resize 时会把 `pod.spec.overhead` 重复计算(开启 InPlacePodLevelResourcesVerticalScaling 时),已修复。这条和上期 IPPR 抢占 beta 是一体的,用 RuntimeClass overhead(例如 Kata 沙箱)的集群在 1.38 前后的行为会不同。https://github.com/kubernetes/kubernetes/pull/144295
- **KEP-5598 Opportunistic Batching 的 "Rescore 扩展点" 方案撤回**:作者关闭了 KEP 更新,先集中做 k/k#144245,让 PodTopologySpread、InterPodAffinity 在默认调度配置下也能参与 pod signing。也就是说,批量调度加速会先覆盖默认 profile,通用 Rescore 扩展点延后。自研插件如果想吃到 batching 加速,要关注 `SignPod` 接口。https://github.com/kubernetes/enhancements/pull/6411 / https://github.com/kubernetes/kubernetes/issues/144245
- 边界提示(归 `k8s-ai-infra`,这里不展开):
  - **DRAPreemption alpha**(v1.38):scheduler 可以抢占低优先级 Pod 独占的节点本地 DRA 设备,并把释放出的设备留给抢占者。这条对通用影响有限,只对用 ResourceClaimTemplate 的设备型工作负载生效。https://github.com/kubernetes/kubernetes/pull/143456
  - KEP-5547 / KEP-6089 / KEP-5732 冻结后已把 KEP 文档与代码对齐。

## 节点 & kubelet

- **GA(v1.38)**
  - **PodLevelResources GA**:`spec.resources` 可以在 Pod 级别设置 CPU/内存的 request 和 limit,容器之间共享这份预算。https://github.com/kubernetes/kubernetes/pull/140536
  - 配套行为变化:
    - **ResourceQuota 校验收紧**:Pod 只设了一部分 Pod 级资源时,剩下的、配额要求的 CPU/内存 request/limit 必须在 Pod 级或每个容器(含 init 容器)上写全,否则会被拒。https://github.com/kubernetes/kubernetes/pull/144273
    - init 容器的 limit 不能超过 Pod 级 limit。由新的 `PodLevelResourcesFixInitContainerLimits` 控制,默认开。https://github.com/kubernetes/kubernetes/pull/143998
    - 这两条会让**原来能创建的 Pod 被拒**,产品里的 Pod 模板生成器要自查。
  - **InPlacePodLevelResourcesVerticalScaling GA**:Pod 级资源可以原地 resize。https://github.com/kubernetes/kubernetes/pull/143999
    - 配套修复:pod cgroup 更新失败或 kubelet 在 resize 中途重启时,cgroup 会停在旧值,现在会对账修正(https://github.com/kubernetes/kubernetes/pull/144234)。
    - 新增 Pod 级 resize 指标 `kubelet_pod_requested_resizes_total`(https://github.com/kubernetes/kubernetes/pull/144232)。
- **beta 默认开(v1.38)**
  - **ContainerScopedProbes**:探针 worker 改为跟容器实例的生命周期绑定:只在容器启动后才开始探测,容器停止后立即停探;kubelet 重启后直接沿用已有状态,不会再造成 readiness 抖动,也避免了 sidecar 死锁;不再对正在终止的容器做 exec 探测。对长启动的推理服务(startupProbe → readiness 串行)行为更可预期。https://github.com/kubernetes/kubernetes/pull/144020
- **alpha(v1.38)**
  - **PerPodPIDLimit**(KEP-6063):`spec.resources.limits.pids`,实际生效值是 min(节点 podPidsLimit, Pod 级值)。要求 cgroup v2,且依赖 PodLevelResources。多租户防 fork bomb 可以细化到单个 Pod。https://github.com/kubernetes/kubernetes/pull/139277 ;KEP 文档对齐(LimitRange 不接受 pids,status 也不上报,两者都推到 beta)。https://github.com/kubernetes/enhancements/pull/6529
  - **WorkloadControlledSwap**(KEP-5359):容器级和 Pod 级都可以声明 `resources.limits.swap`,并且能通过 resize 原地修改。https://github.com/kubernetes/kubernetes/pull/142885
  - **DynamicNodeLocalEphemeralVolumes**:通过 `/dynamic` 子资源向运行中的 Pod 增删 emptyDir、configMap、secret、projected、image 卷。新卷要配合 DynamicContainers 新增的容器才能挂载,已有容器不能改 volumeMounts。和上期的 DynamicContainers 合起来,Agent 沙箱可以"运行时挂工具镜像"。https://github.com/kubernetes/kubernetes/pull/143709
  - **CgroupNamespacesSupport**(KEP-5714):可以声明是否 unshare cgroup namespace。apiserver 会拒绝 `hostUsers: false` 配 `hostCgroupNamespace: true`,containerd main 也在 CRI 层同步拒绝这一组合。https://github.com/kubernetes/kubernetes/pull/143673 / https://github.com/containerd/containerd/pull/14643
  - **NodeMemoryReservationPolicy**(KEP-2570 MemoryQoS):`Soft` 用 memory.low、`Hard` 用 memory.min 保护 Guaranteed/Burstable 的内存 request。https://github.com/kubernetes/kubernetes/pull/142854
- **其他修复(v1.38)**
  - **独占 CPU 的 Guaranteed Pod 支持 IPPR 改 CPU**(InPlacePodVerticalScalingExclusiveCPUs):static CPU manager 下的 Guaranteed Pod 终于可以原地调整 CPU。https://github.com/kubernetes/kubernetes/pull/140629
  - 前置改造:kubelet 把 resize 准入改成事务式(先在临时状态里试算,持久化成功后再提交 cpuset),防止 resize 被拒后 cpuset 被污染。https://github.com/kubernetes/kubernetes/pull/143400
- **patch 版本修复**(v1.37.3 / v1.36.7)
  - 同名节点快速重建后 kubelet 不能注册 CSINode。https://github.com/kubernetes/kubernetes/pull/143771
  - 1.36.7:修复 1.35 起的回归,Pod 开始优雅终止后 exec readiness 探针报 "context canceled" 并停止执行;subpath 挂载点损坏(例如 NFS stale handle)导致 Pod 卡在 CreateContainerConfigError,现在可以自愈。https://github.com/kubernetes/kubernetes/blob/master/CHANGELOG/CHANGELOG-1.36.md
- **新 KEP / KEP 更新**
  - **KEP-6523 kubelet 支持 HugeTLB 内存记账**(provisional,cgroup v2):提出把内存和大页合并成一个固定预算,驱逐和 MemoryQoS 的取舍还没定。https://github.com/kubernetes/enhancements/pull/6524
  - **KEP-6007 NUMA 利用率感知的 Topology Manager 选项**:更新提高 single-numa-node 密度的方案。https://github.com/kubernetes/enhancements/pull/6522
  - **KEP-3953 节点资源原地变更 Layer 2**:支持非热插拔的 VM resize(由 `Node.Spec.ConfiguredCapacity` 驱动);缩容放不下现有 Pod 时进入 Deferred、不驱逐,只有物理容量真的丢失时才驱逐。https://github.com/kubernetes/enhancements/pull/6484
