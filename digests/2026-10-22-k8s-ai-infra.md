# K8s AI 基础设施周报 2026-10-22

> 窗口:2026-10-15 ~ 2026-10-22(过去 7 天)。GitHub API 抓 releases + merged PR + KEP。
> 边界:本期只收 AI-specific 组件 + kube-scheduler 的 AI 方向原生演进(详见 task 边界说明)。

## 摘要(3 条以内)

1. **上游原生调度本周"双线推进":Topology Aware Scheduling(KEP-5732)在 v1.37 周期合入 beta 提升 PR,同时 Composite Pod Group(CPG,分层 PodGroup)API 本周一口气合了 ~10 个实现/校验/抢占/性能 PR。** 这两条正好打在 Volcano 最硬的两块地盘——gang 分层 + 拓扑感知——上游在原生化。
2. **LWS 发 v1.0.0 正式 GA**:DisaggregatedSet 新增"可独立伸缩子角色""滚动更新中伸缩""分片滚动窗口",配置 API 升 v1;原生 gang(KEP-666,基于 PodGroup)仍是 alpha/opt-in。NFD 发 v0.20.0,NodeResourceTopology 改用 server-side apply(减半 apiserver 压力),已对齐 k8s 1.37 库——**升级有 RBAC 硬动作**。
3. **生态侧在"接入"而非"对抗"原生 WAS**:JobSet v0.13.0 加了 alpha WAS 集成(直接创建原生 Workload + PodGroup),Grove alpha.16 加了 Kueue 预构建 workload 后端,Kueue 继续把 DRA/Workload 当默认路径追。趋势:生态调度器正从"自己拥有 gang 逻辑"转向"做原生 Workload/PodGroup 原语的消费者/翻译层"。

## GPU / 加速器管理

- **NFD v0.20.0**(2026-10-16,过去 7 天内)https://github.com/kubernetes-sigs/node-feature-discovery/releases/tag/v0.20.0
  - nfd-topology-updater 写 NodeResourceTopology 改用 **server-side apply**(字段管理器 forced):每次更新从"GET+UPDATE 两次请求"降到一次 patch,大规模集群显著降 apiserver/etcd 压力。
  - 已对齐 **Kubernetes v1.37 库**(k8s.io/* v0.37.1,k8s.io/kubernetes v1.37.1),构建升 **Go 1.27**。NFD 是加速器特征发现的底座,库版本跟到 1.37 意味着它已跑在最新调度能力之上。
  - **升级硬动作(Action Required)**:topology-updater 的 ClusterRole 对 `noderesourcetopologies` 权限由 `create,get,update` 改为 `create,patch`。只 bump 镜像不改 RBAC 会在首次更新 crash-loop;滚动升级/回滚期间需同时授 `create,get,update,patch`。自管 RBAC 的务必提前处理。
  - kubelet 配置读取现在 2 分钟超时且失败不再退出(改为用缓存 + 跳过发布 + 计数 `nfd_topology_updater_scan_errors_total`);靠 topology-updater 重启做告警的要改看这个 metric。
- **NVIDIA/gpu-operator v26.7.2**(2026-10-14,窗口前 1 天,补记)https://github.com/NVIDIA/gpu-operator/releases/tag/v26.7.2 —— 26.7.x 补丁线,非功能性大改。
- NVIDIA/k8s-device-plugin 本窗口无新 release(最新 v0.20.1,2026-09-22)。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

本周是 v1.37 周期里 WAS 落地最密集的一周,**两条主线同时推进**:

**(1) Topology Aware Scheduling → beta(KEP-5732)**
- `[WAS] KEP-5732: Promote TAS to beta` #140295,merged 2026-10-21 https://github.com/kubernetes/kubernetes/pull/140295
- 原生拓扑感知调度进 beta,意味着默认开启的路径更近了。**直接对标**:Kueue 的 TAS、Volcano v1.16 的 HyperNode/PodGroup 拓扑反亲和。本周 Kueue 侧也有多个 TAS bugfix(见下),说明 Kueue 的 TAS 是建立在同一套原生原语之上的消费者,而非竞品——这是"利好/被收编"的典型信号。
- 配套:#140308 空拓扑标签值视为无效 TAS 域、#141929 TAS 指标按实体类型参数化。

**(2) Composite Pod Group(CPG,分层 PodGroup)API 密集实现**
- #141860 为 CPG 实现递归状态 https://github.com/kubernetes/kubernetes/pull/141860
- #142830 扩展 Workload API 校验(merged 10-20)https://github.com/kubernetes/kubernetes/pull/142830
- #143055 PodGroup 与 Workload API 中 CPG 字段的 enable/disable 单测
- #142951 抢占中移除 group priority 查找与 nil-lister 分叉、#142684 修 podgrouppreemption 中低优 Pod 的 NNN 清理、#142928 PodGroupInfo.Children 改为非导出
- #143209 把 pod group 层级遍历抽到 plugins/helper、#142625/#141466 CPG 测试、#141706 CPG 性能测试
- 判读:CPG = **原生的分层/嵌套 PodGroup + 原子成组调度**,这正是 Volcano PodGroup gang + 分层队列的核心能力。上游把它做成一等公民并补齐递归状态/抢占/性能,**Volcano gang 的独占性在被稀释**(task 里标注的"常设研判题")。时间线锚点吻合:v1.37 两个 feature gate 要合并为 `GenericWorkload` 冲 beta。

**WAS 研判(挤压 vs 利好)**
- **被挤压**:Volcano——gang 成组 + HyperNode 拓扑两块同时遇到原生替代(CPG + TAS beta)。中长期纯 gang 卖点会变薄,需往"策略丰富度/多租户/异构卡纳管"差异化(v1.16 的 NamespaceQueue/fairshare/UnschedulableJobCache 正是这个方向)。
- **被利好/收编**:Kueue——已把 Workload/DRA/TAS 当默认追,原生原语越成熟,Kueue 越像"队列/配额层"的天然落点。
- **对我们产品的启示**:若自研调度栈押在"自己实现 gang"上,要重估 6~12 个月后的技术债;更稳的下注是"对接原生 Workload/PodGroup API 做配额/多租户/异构调度策略层",与 Kueue 走同一方向。

### Kueue
- **v0.20.2 + v0.19.9**(均 2026-10-15)https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.2 —— 两条维护线同步出补丁,以 bugfix 为主。
- **DRA**:修了 Workload 在被调度期间更新会按旧 spec 计配额、导致过/欠准入的 bug(#17208)——DRA + 配额路径在打磨准确性。
- **TAS** 多处修复:非相邻 PodSet 组(如 JobSet)起 Pod 时串了别的 PodSet 标签/节点选择器(#17089)、拓扑抢占遗漏重叠 flavor(#16919,需 `TASHandleOverlappingFlavors`)、required 拓扑放置失败信息更清晰(#17172)。
- 安全相关:修 Pod 通过伪造 `role-hash` 注解绕过 ClusterQueue 配额跑超规格 Pod 的漏洞(新增 alpha gate `PodIntegrationVerifyRoleRequests`,默认关)。
- KueueViz 现能展示 pod group Workload(含 StatefulSet / LeaderWorkerSet)的 Pod。
- 启示:Kueue 把"和 JobSet/LWS/DRA/TAS 的接缝 bug"系统性清一遍,正是它坐实"原生原语之上的配额/队列层"定位的工程表现。

### Volcano / Kthena
- **Volcano v1.16.0**(2026-10-14,窗口前 1 天,因 task 重点收录)https://github.com/volcano-sh/volcano/releases/tag/v1.16.0
  - **NamespaceQueue + fairshare 插件**:租户可在自己 namespace 内管理队列层级/配额(用管理员授权的资源池);共享队列场景引入 Slurm 式历史用量衰减做长期公平。
  - **HyperNode 控制器独立化**:拓扑发现/超节点管理抽成可独立部署的 HyperNode controller + API,**供其他调度器复用**——Volcano 在主动把拓扑能力产品化外供(应对原生 TAS 的一种打法)。
  - **PodGroup 拓扑反亲和**:按 HyperNode 域打散工作负载实例(required/preferred)。
  - **UnschedulableJobCache**(默认关,feature gate):缓存 Job 不可调度原因 + 插件事件提示,后续 session 跳过重复检查,大 backlog 下提速。
  - 其他:K8s 1.36 支持、**DRA 评分**、队列级 nodegroup 配额、加速器增强。
  - 判读:v1.16 的发力点(多租户 NamespaceQueue + 公平性 + 调度性能 + 拓扑外供)正好避开和原生 CPG/TAS 正面硬刚,往"策略深度 + 异构 + 规模"差异化走。昇腾调度栈(ascend-for-volcano / HAMi vgpu)压在主仓上,v1.16 的 API/release 变化需关注下游三个 watch task 的兼容。
- **Kthena**:本窗口无新 release(最新 v1.0.0,2026-07-16 GA)。推理调度/路由赛道暂无增量。

### DRA
- 本窗口 **dra-evolution 仓无 release**(该仓以设计讨论为主)。DRA 进展主要体现在各消费方:
  - k/k 调度器:#142492 cherry-pick #142289 —— DRA 在 pod claim 迭代与 taint 驱逐中纳入**扩展资源 claim**(extended resource claims),补齐 DRA 与污点驱逐的交互。
  - Kueue #17208(配额重算,见上)、Volcano v1.16 DRA 评分、JobSet v0.13 共享 DRA resource claim(见下)。
- 启示:DRA 已从"核心机制定义"阶段进入"全家桶消费方逐个对接"阶段(调度器 / 配额 / 批作业 / 拓扑同时在接)。这是 DRA 取代 device-plugin 的必经工程化阶段,**我们的加速器方案要开始规划 DRA 适配路线,不能再只押 device-plugin**。

### LWS / JobSet
- **LWS v1.0.0 GA**(2026-10-16)https://github.com/kubernetes-sigs/lws/releases/tag/v1.0.0
  - DisaggregatedSet:**可独立伸缩子角色**(一个 role 切成独立伸缩/路由池共享同一 workload 配置,KEP-960)、**滚动更新中继续 scale-up + opt-in scale-down**(KEP-1022)、**分片滚动窗口**(按副本数比例推进,更充分用 maxSurge/maxUnavailable,PR #907)。
  - **原生 gang 调度**(KEP-666,基于 PodGroup):修了 PodGroup 生命周期与组大小更新,但**仍是 alpha / opt-in**——LWS 也是原生 PodGroup 的消费者。
  - 恢复能力:`maxGroupRestarts` 限制副本组自动重建次数 + `restartBackoff`(KEP-820);`podTerminationPolicy: Parallel` 并行终止 leader/worker。
  - 配置 API 升 **config.lws.x-k8s.io/v1**(v1alpha1 保留但弃用)。
  - **升级硬动作**:无 rollingUpdateConfiguration 的 DisaggregatedSet role 默认值变为 maxSurge 0 / maxUnavailable 1(与 LWS 对齐);v1.0.0 移除对 v0.9.x 生成的 slice-less LWS 的支持,受影响对象需先在 v0.10/v0.11 完成一次模板滚动再升。OAI 已在用 LWS,升级前务必读 Urgent Upgrade Notes。
- **JobSet v0.13.0**(2026-10-12,窗口前,因与 WAS 主线强相关补记)https://github.com/kubernetes-sigs/jobset/releases/tag/v0.13.0
  - **alpha WAS 集成**(gate `JobSetWorkloadAwareSchedulingAPI`,默认关):`spec.scheduling` 支持整个 JobSet / ReplicatedJob 组 / 单个 Job 副本的 Basic 或 Gang 调度,**直接创建并 reconcile 原生 Workload + PodGroup**,子 Pod 经 `schedulingGroup.podGroupName` 映射;支持共享 DRA resource claim(alpha 暂不含 composite PodGroup 层级)。
  - 这是本期 WAS "生态接入"的最硬证据:JobSet 不再自己实现 gang,而是生成原生 Workload/PodGroup 交给 kube-scheduler。
  - 另有 alpha active deadline(`JobSetActiveDeadlineSeconds`)、alpha 执行尝试追踪、TLSOptions 升 GA。
