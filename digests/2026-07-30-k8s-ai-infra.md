## KEP 动向

DRA 是本周最强信号,三条 KEP 覆盖从 alpha 到 GA 全阶段:

- **KEP-6080 DRA: Derived Attributes → 提 beta**(PR #6255,open;sig/scheduling + wg/device-management)。给 `DeviceRequest` 加 `derivedAttributes`(scoped CEL 表达式),**在跨厂商、属性 schema 不一致的设备间做灵活的内联协同分配(co-allocation)**。若进 beta,多芯片/多厂商 GPU·NPU 的"按能力协同选设备"将成上游标准能力。 https://github.com/kubernetes/enhancements/pull/6255
- **KEP-5007 DRA: Device Binding Conditions → 冲 GA**(PR #6005,open;beta→stable)。面向 **fabric/网络挂载设备**:pod 调度前需先把设备 attach 到节点。文档正推进 milestone(PR 标题写 1.38,正文按 v1.37 改 latest-milestone,尚在讨论)。与池化/远程 GPU、CXL 设备调度直接相关。 https://github.com/kubernetes/enhancements/pull/6005
- **KEP-5517 DRA: Node Allocatable Resource Requests → 更新 alpha2 API**(PR #6257,**merged**;sig/node + sig/scheduling)。用 DRA driver 管**核心资源**(如 `dra-driver-cpu`),解决 kube-scheduler 标准记账与 `DynamicResources` 插件**双向互不感知、可能资源重复记账**的问题。意味着 DRA 从加速器外溢到 CPU/整机资源,长期可能统一整机资源模型。 https://github.com/kubernetes/enhancements/pull/6257
- **KEP-5710 PodGroupPreemptionPolicy 补文档 + 独立 feature gate**(PR #6222,merged)。Pod 组级抢占策略,与 AI 侧 gang scheduling 相邻;实现里该字段漏了,故拆独立 gate 以免拖慢 GenericWorkload 主特性晋级——未来做批任务/组调度时,抢占策略将有原生字段可用(核心侧记账见 k8s-core 周报)。 https://github.com/kubernetes/enhancements/pull/6222
- (背景)**KEP-6132 PreQueueingHint beta→alpha 回退**:调度事件把 Pod 从 unschedulable 队列拉回 active 队列的扩展点,1.37 内降级默认关闭,影响大规模集群调度吞吐——详见 k8s-core 周报。 https://github.com/kubernetes/enhancements/pull/6261

## 值得跟进

- [ ] **DRA Derived Attributes(KEP-6080)进 beta 前评估**:跨厂商属性协同分配若成标准,我们的多芯片调度选型要判断"直接押 DRA + CEL"还是继续自研 label/注解匹配——押上游能省长期维护,但 CEL 表达能力与性能需实测。
- [ ] **gpu-operator GPUCluster CRD 稳定度跟踪**:这是 NVIDIA 官方 DRA 栈的编排入口,盯其 API 是否会破坏性变更,决定我们 GPU operator 层是否跟迁到 DRA 栈。
- [ ] **Node Allocatable DRA / dra-driver-cpu(KEP-5517)**:DRA 管 CPU 核心资源 = 整机资源记账可能统一,直接影响我们整机调度与超卖/记账架构,长期重点。
- [ ] **Kueue DRA 配额记账成熟度**:多租户 GPU 配额若走 DRA,Kueue 是上游事实标准(AdminAccess 排除、consumable capacity 已在补),评估我们配额层是否整合而非自建。
- [ ] **Device Binding Conditions GA(KEP-5007)**:fabric-attached / 远程 GPU 在调度前置 attach,与设备池化、CXL、网络挂载加速器方向强相关,GA 后可作为池化调度的上游底座。
- [ ] **LWS DisaggregatedSet(#922)**:P/D 分离推理的原生 K8s 编排能力在补齐,与 OAI/vLLM disagg 路线对齐,评估作为我们推理编排层的候选。
