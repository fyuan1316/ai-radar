# K8s 自身核心周报 2026-09-17

窗口:2026-09-10 → 2026-09-17

## 摘要(3 条以内)

- **v1.38 enhancements 冻结潮**:`kubernetes/enhancements` 本周被一批"目标 v1.38 alpha/beta/GA"的 KEP PR 刷屏,是 1.38 周期的能力冻结信号。抛开归 `k8s-ai-infra` 的 DRA/WAS/gang 线,通用侧最值得盯的是 **In-Place Pod Resize 的调度器抢占补齐(KEP-5836 beta)**、**容器 probe 就地更新(KEP-6318)**、**SPDY→WebSocket 转型 GA(KEP-4006)** 三条。
- **运行时集体追平 1.37**:containerd **v2.4.0** GA(非 LTS、含 breaking/去弃用)、CRI-O **v1.37.0** GA(对齐 k8s 1.37);containerd 2.4 把 CRI 镜像挂载切到 mount manager、默认打开 UserNamespacesHostNetwork,升级前需先清掉 2.3 的 deprecation 警告。
- **策略侧是安全补丁窗口**:Kyverno **v1.19.1** 是一轮 CVE/SSRF 密集修补(apiCall.service egress SSRF 加固、IVPol PolicyException 作用域绕过 GHSA-5cjf-wwfg-pj4c、两个 Go CVE),用 Kyverno 的应尽快升级。

## 调度(kube-scheduler)

只写**通用**调度改动;WAS / gang / Workload API / TAS / DRA 抢占等归 `k8s-ai-infra`,此处不复述。

- **KEP-5836:In-Place Pod Resize 的调度器抢占 → beta(目标 v1.38)** https://github.com/kubernetes/enhancements/pull/6344
  当 Pod 就地扩容(IPPR)导致节点容量不足时,让调度器介入做抢占。这是 IPPR 从"能改 request"走向"生产可用"的关键一环,直接关系 VPA 就地生效链路(见下)。
- **KEP-6132:PreQueueingHint → beta(目标 v1.38)** https://github.com/kubernetes/enhancements/pull/6374
  调度队列的 QueueingHint 框架继续成熟,减少 Pod 在 unschedulable 队列里的无效重试,对大规模集群的调度吞吐是通用增益。
- **KEP-6352:Node Allocatable Capacity Reservation(新 KEP)** https://github.com/kubernetes/enhancements/pull/6353
  在 node allocatable 上预留容量的通用机制,值得关注它与我们做 GPU/系统预留的重叠。

## 节点 & kubelet

sig-node 是本周 KEP 活动最密集的 SIG,挑通用且对产品有影响的:

- **KEP-6318:容器 probe 就地更新 → 允许 in-place 修改探针** https://github.com/kubernetes/enhancements/pull/6323
  不重建 Pod 就能调 liveness/readiness 探针,和 IPPR 同属"减少 Pod 重建"大方向。
- **KEP-6249:为 DaemonSet 协调发布 Graceful Node Shutdown 状态** https://github.com/kubernetes/enhancements/pull/6351
  节点优雅关机时把状态暴露给 DaemonSet,便于 CSI/网络/监控类 DS 在关机前有序退出——对存储/网络插件的下线正确性有直接影响。
- **KEP-5683:kubectl drain 报告节点 conditions** https://github.com/kubernetes/enhancements/pull/6309 —— 运维可观测性小改进。
- **KEP-6030:memory-backed volume 动态 resize → beta** https://github.com/kubernetes/enhancements/pull/6320
- **KEP-5474:cgroup mount mode 的 CRI API + writable cgroups**(alpha 落 v1.38,含实现反馈)https://github.com/kubernetes/enhancements/pull/6260 、 https://github.com/kubernetes/enhancements/pull/6366
- **KEP-6252:Hugepages Reservation(新)** https://github.com/kubernetes/enhancements/pull/6253 、**KEP-6007:NUMA 利用率感知的 topology manager 策略** https://github.com/kubernetes/enhancements/pull/6332 —— 大内存/NUMA 亲和场景,和 AI 推理节点资源规划相关。
- **KEP-5972:Dynamic Containers** https://github.com/kubernetes/enhancements/pull/6169 —— 运行中 Pod 动态增删容器方向,长期看影响 sidecar/debug 模型。

> 提示:`GPU support for Pod-level Checkpoint/Restore`(KEP-6274)偏 AI/设备语义,按边界归 `k8s-ai-infra`,此处不展开。

## 自动扩缩容(VPA / CA / Karpenter)

- **VPA:本周无新特性**。要跟的仍是 **In-Place Pod Resize 线**——本周的进展在调度器侧(上文 KEP-5836 抢占 beta),VPA 本体无提交。IPPR 抢占补齐后 VPA 才能在不驱逐 Pod 的前提下真正生产可用,继续盯这条。
- **Cluster Autoscaler**:
  - AWS CSI 从零扩容修复——补齐 CSI node topology,修 scale-up-from-zero https://github.com/kubernetes/autoscaler/pull/10133
  - CAPI provider:从模板抽取 `topology.kubernetes.io/zone` label https://github.com/kubernetes/autoscaler/pull/10258 ;GCE 对非 GCE ProviderId 节点的处理改进 https://github.com/kubernetes/autoscaler/pull/10274
- **Karpenter**:本周只有 metrics 打磨,无新特性——把 disruption 决策维度拆成 command vs approval https://github.com/kubernetes-sigs/karpenter/pull/3322 、给 unknown cloudprovider error 命名 https://github.com/kubernetes-sigs/karpenter/pull/3323 。
- **Cluster API**:**in-place update 线在推进**——为 MachineDeployment / KCP 实现 `AffectsAvailability` https://github.com/kubernetes-sigs/cluster-api/pull/14195 、 https://github.com/kubernetes-sigs/cluster-api/pull/14200 ;cloud-init 支持 `write_files` defer https://github.com/kubernetes-sigs/cluster-api/pull/14182 。CAPI 的就地更新与 K8s 本体 IPPR 是同一"少重建"哲学的不同层。
