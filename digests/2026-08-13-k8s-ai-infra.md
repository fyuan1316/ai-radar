# K8s AI 基础设施周报 2026-08-13

覆盖窗口:2026-08-06 ~ 2026-08-13(上期 2026-08-06)。数据源为各仓 GitHub API releases + merged PR,已过滤 CI/依赖 bump/chore 噪声。

## 摘要(3 条以内)

1. **原生 Gang Scheduling 进 beta,随 v1.37 落地**:KEP-4671(Gang Scheduling)在 v1.35 alpha 后,于 v1.37 升 beta,`v1.37.0-rc.0` 已于 08-06 切出。这是 kube-scheduler 自身(wg/workload-aware-scheduling)提供的原生 gang,长期会与 scheduler-plugins Coscheduling / Kueue 的 CRD 方案形成竞合——我们的调度选型要开始把"原生 gang beta"纳入路线图。https://github.com/kubernetes/enhancements/issues/4671
2. **LWS v0.10.0 发布,DisaggregatedSet(P/D 分离服务)成体系**:本版把 DisaggregatedSet 从骨架推到可用——补 `.status` 上报、per-role HPA(KEP-849)、placement policy、slices 字段。这是 K8s 原生的 prefill/decode 分离推理编排,直接对标我们推理平台的分角色伸缩能力。https://github.com/kubernetes-sigs/lws/releases/tag/v0.10.0
3. **Kueue v0.19.1 / v0.18.5 双版本**:一堆 Admission Fair Sharing(AFS)正确性修复 + 新增 `AfsUsageLedger`;修了 LWS 改 `size` 绕过配额的漏洞(新 `LWSImmutableGroupSize` 门控,beta 默认开);DRA 扩展资源配额聚合 bug 修复。升级前必读 Actions Required。https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.1

## GPU / 加速器管理

NVIDIA/gpu-operator 本周主要是 DRA 与可观测链路的打磨(无 ClusterPolicy CRD 字段变更):

- **DRA computedomain 插件补 node 权限**(#2714):权限对齐 dra-driver-nvidia-gpu 的 kubeletplugin RBAC。DRA 路径在 gpu-operator 里持续补齐,是 device-plugin 之后的既定方向。https://github.com/NVIDIA/gpu-operator/pull/2714
- **dcgm-exporter 按 env 自动挂 ServiceAccount token**(#2721):此前只有 `enablePodLabels/enablePodUID` 字段触发挂 token;通过 `dcgmExporter.env` 配同类特性(如 `DCGM_EXPORTER_CONFIGMAP_DATA`)的用户被漏掉,导致读不到 token 而崩溃。本次让"env 里读 ConfigMap / 开 pod 富化"也挂 token 并配套集群级 RBAC。https://github.com/NVIDIA/gpu-operator/pull/2721
- **驱动就绪走 sentinel 文件**(#2727):新增 `.driver-daemons-status` 哨兵文件,确保 Fabric Manager 等 daemon 全部起来后驱动容器才进 Running;文件不存在时不强制,向后兼容旧驱动镜像。配套 gpu-driver-container#913。https://github.com/NVIDIA/gpu-operator/pull/2727
- 其余:distroless 用户名修正(#2730)、computedomain 的 dcgm-exporter Role 收敛(#2726/#2724)、vgpu-device-manager DaemonSet 补 toleration(#2725)。

NVIDIA/k8s-device-plugin、NFD、dra-evolution 本周无实质变更(仅依赖 bump / THIRD_PARTY_NOTICES 生成工具)。

## 调度 & 资源分配

### Kueue(v0.19.1 + v0.18.5,08-12)

升级前硬约束(Actions Required):

- **LWS 配额绕过修复**:对已 admit 的 Kueue 托管 LeaderWorkerSet 抬高 `leaderWorkerTemplate.size` 会跑超配额的 pod。现 `size` 在 Kueue 托管期间不可变,由新门控 `LWSImmutableGroupSize`(beta,默认开)控制;`replicas` 仍可变。要变 size 需重建。(#13809)
- **TAS 更严的 slice 校验**:`podSetSliceRequiredTopology` 必须搭配 `podSetSliceSize > 0`,否则拒绝;直接建 Workload 的自定义控制器要先改 manifest。(#13737)。另修 `TASRecomputeAssignmentWithinSchedulingCycle` 在 TAS 关闭时仍可被启用的 bug(#14257)。

特性 & 修复:

- **AFS(Admission Fair Sharing)一轮硬化**:新增按 Workload 统一记账的 `AfsUsageLedger`(#14153),并修多个 AFS 缺陷——`weight:0` 队列被错误优先、小于 1 milli 的用量被截断成 0 导致 GPU 用量永远记不上、AdmissionChecks 通过的 workload entry penalty 永久残留等(#13559/#13761/#13795/#13851)。AFS 是多租户公平调度的核心,这批修复对生产可用性关键。
- **DRA 扩展资源配额聚合修复**(#14200):`ResolveExtendedResourceQuota` 原先"先映射到 quota key 再跨容器聚合",非线性聚合导致两个不同扩展资源名映射到同一 quota key 时相互吞掉贡献;改为先按原始名聚合再映射。DRA + Kueue 配额结合的正确性问题。https://github.com/kubernetes-sigs/kueue/pull/14200
- **MultiKueue 转发 RayService serveConfigV2**(#14036):在 manager 侧改 Ray Serve 应用配置能及时下发到 worker 集群;`rayClusterConfig`/零停机升级策略尚未传播。

### DRA

- 本周 DRA 的动向集中在下游消费侧(gpu-operator computedomain 权限、Kueue 扩展资源配额),`kubernetes-sigs/dra-evolution` 主仓无新提交。DRA 仍是重中之重,继续跟 device-class / extended-resource 与 Kueue 配额的整合成熟度。

### LWS / JobSet

- **LWS v0.10.0(08-11)** —— 本版核心是 **DisaggregatedSet**(P/D 分离服务)从骨架到可用:
  - `.status` 上报落地(#933):新增 `status.observedGeneration` 与 per-role `replicas/readyReplicas/updatedReplicas`,按 owner UID 过滤 LWS 聚合,支撑 CRD printer columns、让 rollout 可见。
  - **per-role HPA / 自动伸缩**:KEP-849 per-role HPA 支持(#910)+ `DisaggregatedSetRoleScaler`(#922),可对 prefill / decode 角色分别伸缩——这正是分离推理的关键能力。
  - **placement policy**(#916)与 **slices** 字段(#873):控制角色放置与切片。
  - 另有 webhook 校验(replicas 上限 100 万、maxSurge/maxUnavailable 不能同 0)、metadata 向 StatefulSet 传播、SubGroup 相关修复。https://github.com/kubernetes-sigs/lws/releases/tag/v0.10.0
- **JobSet**:仅 #1252 补 e2e 测试,无功能变更。

## KEP 动向

- **KEP-4671 Gang Scheduling → beta(v1.37)** ⭐:`stage: beta`,`alpha: v1.35 / beta: v1.37`,归 sig/scheduling + wg/workload-aware-scheduling。#6266 将 KEP 同步到 v1.37 final state,`v1.37.0-rc.0` 已于 08-06 切出。含义:kube-scheduler 将原生支持 gang(协同调度一组 pod,全有或全无),不再必须依赖 scheduler-plugins Coscheduling 或 Kueue 的 workload 层。对我们:训练/多节点推理的 all-or-nothing 调度将有上游原生底座,需评估与现有 gang 方案的迁移/共存路径。https://github.com/kubernetes/enhancements/issues/4671
- 本窗口 enhancements 仓无其它 AI/GPU/DRA 相关 KEP 的新增或状态变更(仅上述同步 + sig-testing leads 更新)。
