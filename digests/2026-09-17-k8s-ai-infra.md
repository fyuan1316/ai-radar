## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

本周是 kube-scheduler AI 主线信息量最大的一周。KEP 层面:

- **KEP-4671 Gang Scheduling → `stage/stable`**(`tracked/yes`,wg/workload-aware-scheduling)。native gang 已进入冲 GA 的阶段。
- **KEP-5710 Workload-aware preemption → `stage/stable`**。workload 粒度抢占也在冲 GA。
- 代码侧一批 merged PR 印证机制在快速成熟:
  - `Refactor pod group preemption to use GenericPodGroup`(#141934)——把 PodGroup 抢占抽象到统一 `GenericPodGroup`,正是 v1.37 `GenericWorkload` 合并两门控的地基。
  - `Validate child pod groups for equal priority and preemptionPolicy`(#141930)——PodGroup API 层校验子组一致性。
  - `Add topology spreading gang preemption performance scenarios`(#140408)、`Add scheduler-perf test cases with larger pod groups`(#141547)——gang 抢占的规模化性能基线。
  - `scheduler: respect NominatedNodeName in TAS placement selection`(#139472)、`Clear PlacementCycleState for pods that move to binding`(#140986)、`Expose PlacementFeasible as an extension point`(#141314)——WAS 放置周期(placement cycle)的扩展点与状态机在补齐。
  - https://github.com/kubernetes/kubernetes/pull/141934
  - https://github.com/kubernetes/kubernetes/pull/141314
  - https://github.com/kubernetes/kubernetes/pull/139472

**研判(WAS 原生化 vs 生态调度器)**:gang 与 workload-aware preemption 同时进 stable、GenericPodGroup 抽象落地,意味着"成组调度 + 组级抢占"这两块 Volcano/scheduler-plugins 的核心差异化,上游正在原生收编且已到 GA 前夜。生态调度器的护城河将从"能不能 gang"转向"gang 之上的策略层"(队列/配额/公平/拓扑/异构卡编排)——Kueue 早已把自己定位在配额与 Workload 编排层(见下),这是正确的避让方向;Volcano 若继续把价值主要压在 gang 独占性上,6 个月后会更被动。我们产品的调度选型应假设:**native gang 明年进 GA,分层设计里不要把 gang 当自研壁垒,壁垒放在配额治理 / 异构加速卡(昇腾)拓扑感知 / 推理路由这些上游短期不碰的层**。

### Kueue

发布 **v0.20.0-rc.0**(以及 patch v0.19.4 / v0.18.8,均 09-10)。重点:

- **DynamicQuotaOrchestration**:新增同名 API(#14557),并给 `ClusterQueue`/`Cohort` v1beta2 加 `status.effectiveQuotas`(#14389)——动态配额分配框架成形。
- **v1beta2 收口**:v1beta1 类型/资源置为 `served: false`,提供 `hack/migrate-to-v1beta2.sh` 强制过一遍转换 webhook(#14558)。升级前需按 release notes 处理 DRA device-class 映射 / `pods` 保留名冲突,否则 controller 起不来。
- **LWS 配额绕过修复**:已 admit 的 Kueue 托管 LWS 若抬高 `leaderWorkerTemplate.size` 会跑超额 pod;现该字段在 Kueue 托管期不可变,门控 `LWSImmutableGroupSize`(Beta 默认开)(#13279)。
- **DRA**:AdminAccess 设备请求改为零配额计费而非拒绝(#13642,AdminAccess 是对已分配设备的只读共享)。
- **MultiKueue**:worker 侧 Ray in-tree autoscaling 支持弹性作业(KEP-13243,#13494);新增 MultiKueue 控制面性能基准(#13936)。
- **TAS**:更严的 slice-size 校验(`podSetSliceSize` 必须 >0 且与 `podSetSliceRequiredTopology` 配套,#12728);修 `TASRecomputeAssignmentWithinSchedulingCycle` 可在 TAS 关闭时被误开(#14237);多个 leader 放置可行性检查修复(#15678/#15447/#15571)。
- **Quota Release Strategy per integration**(KEP-10076,#15146)落地;注意 `scheduling.quotaReleaseStrategy` 配置字段本 release 内先加(#13224)后又 revert(#15371),本版不对外暴露该字段。
  - https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.0-rc.0
  - https://github.com/kubernetes-sigs/kueue/pull/14557
  - https://github.com/kubernetes-sigs/kueue/pull/13494

**研判**:Kueue 持续把 DRA / Workload / 动态配额当默认主路径追,与上游 WAS 分层互补而非对撞——这印证了上一节的避让判断。DynamicQuotaOrchestration 值得单独盯,它是多租户弹性配额的产品化方向,和我们的配额治理诉求高度重叠。

### DRA

DRA 是本期第二大主线,信号密集且都指向"转正":

- **`DynamicResourceAllocation` feature gate 移除**(#141946):1.35 锁定默认开,满三个 release 于 1.38 删除。DRA 核心不再是可选项。
- **KEP-5007 Device Binding Conditions → GA in 1.38**(#6005,stage/stable)。

- **KEP-5729 DRA: ResourceClaim Support for Workloads → stage/beta**(wg/workload-aware-scheduling)——把 ResourceClaim 提到 workload 级,和 WAS/Kueue Workload API 打通。
- 调度器内 DRA 优化:结构化分配器共享设备查找优化(#142014)、清理不可达的 pending 分配路径(#141879)、DynamicResources filter 集成测试(#141398)。
