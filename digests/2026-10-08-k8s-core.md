# K8s 自身核心周报 2026-10-08

窗口:2026-10-01 → 2026-10-08

## 摘要(3 条以内)

1. **K8s 进入 v1.38 周期**(alpha.2,10/07),多项通用能力晋级:HPA `observedGeneration` GA、Windows CPU/Memory affinity Beta、kube-proxy NFTables localhost NodePorts Beta;同时带一条**强制升级注意**——kubelet user namespace(`hostUsers:false`)的 ID 范围 bug 修复,`/etc/subuid` 配到 4294967295 的节点升级前必须收缩。https://github.com/kubernetes/kubernetes/releases/tag/v1.38.0-alpha.2
2. **In-Place Pod Resize(IPPR,VPA 生产化的前提)本周三条 KEP 推进**:新开 Resize Gates(KEP-6438)、调度器抢占支持转 beta(KEP-5836)、Windows 支持(KEP-6303);VPA 侧 AEP-9970 per-VPA target percentiles 落地,Karpenter 开始接 VPA 预测控制器。
3. **运行时 / 策略**:runc v1.6.0-rc.1 去掉 1024 CPU/node 上限、要求 Go 1.26+;containerd PR 层安全硬化(拒绝未知 runtime handler、拒 `..` 路径穿越);Kyverno ImageValidatingPolicy 并发化 + PSS 策略链收紧。

## K8s 核心版本节奏

- **v1.38.0-alpha.2 发布(10/07,prerelease)**,1.38 周期进行中。本次 alpha 的通用晋级 / 清理:
  - **HPA `observedGeneration` 晋 GA**,`HPAGeneration` feature gate 锁定开启。https://github.com/kubernetes/kubernetes/pull/142386
  - **`WindowsCPUAndMemoryAffinity` Beta 默认开**(Windows 节点的 CPU/内存亲和)。https://github.com/kubernetes/kubernetes/pull/142500
  - **`KubeProxyNFTablesLocalhostNodePorts` Beta 默认开**。https://github.com/kubernetes/kubernetes/pull/142490
  - **`MatchLabelKeysInPodAffinity` feature gate 移除**(能力已 GA,门禁清理)。https://github.com/kubernetes/kubernetes/pull/141744
  - Kubemark 从主仓移除。https://github.com/kubernetes/kubernetes/pull/142700
- **强制升级注意(MUST read)**:kubelet 修复了 `hostUsers:false` 下 user namespace 的 ID 范围多处 bug——不再把 pod 分到以 2^32-1 结尾的无效范围;`kubelet` 用户在 `/etc/subuid`/`/etc/subgid` 的从属 ID 范围若结束于或越过 4294967295(如 `kubelet:65536:4294901760`),升级前必须按 `idsPerPod`(默认 65536)至少收缩一块;被旧 kubelet 分到无效范围、卡在 `ContainerCreating`/`FailedCreatePodSandBox` 的 pod 需先删除或 drain,否则新 kubelet 拒绝启动。https://github.com/kubernetes/kubernetes/pull/141345
- **deep-dive 触发判断**:1.38 仍在 **alpha 阶段**(非 rc.0 / 非正式 tag),`tasks/k8s-release-deep-dive.md` **暂不需要跑**;等 **1.38 rc.0** 或正式 tag 出现再触发全量版本档案。

## 调度(kube-scheduler)

- 本窗口**通用调度器无重大通用能力变更**。WAS / gang / Workload API / CompositePodGroup(本周 alpha.2 新增 `scheduling.k8s.io/compositepodgroup-protection` 终结器与 status 更新、KEP-5547 Job 控制器集成 WAS 转 beta、KEP-6413 PodGroup runtime satisfaction condition)均属 AI 方向原生演进,**归 `k8s-ai-infra`,本任务不重复**。
- 唯一通用溢出:**IPPR 的调度器抢占**(KEP-5836)转 beta——scheduler 为 in-place resize 腾资源时的抢占行为,影响所有用 in-place resize 的工作负载,详见下方自动扩缩容节。https://github.com/kubernetes/enhancements/pull/6344

## 节点 & kubelet

- **user namespace ID 范围修复**(见上方版本节奏的强制升级注意)——这是本周 node 侧最需要动作的一条。
- **kubelet gRPC 探针连接被拒即时失败**:不再重试到探针超时;对无响应服务器的失败信息改为 `timeout: health rpc did not complete within <timeout>`。https://github.com/kubernetes/kubernetes/pull/142457
- **kubelet pods API gRPC server 加限流**:每连接并发流上限 100,并对 `WatchPods` 开流套用请求速率限制。https://github.com/kubernetes/kubernetes/pull/142458
- **分配资源健康状态按确定顺序上报**,避免健康未变时触发无谓 pod status 更新。https://github.com/kubernetes/kubernetes/pull/142340
- KEP 动向:**KEP-6318 明确可变探针(mutable probe)行为**(merged);**KEP-6416 Kubelet Parallel Container Operations**(WIP 新开,并行容器操作,启动延迟优化线);**KEP-5359 workload controlled swap** 文档合入(swap 方向继续);**KEP-6249 为 DaemonSet 协调发布优雅节点关闭状态**(WIP)。

## API Machinery & Operator 生态

- **KEP-6268 慢 watch 流"暂停并恢复"而非终止**(merged):apiserver 在 watch 消费者慢时不再直接终止流,改为 stall/resume——对高负载下大量 controller 的稳定性是正向改动,值得跟。https://github.com/kubernetes/enhancements/pull/6269
- **apiserver 接受最多 16384 个 request header values**:修 Go 1.27 默认 500 header 上限导致被冒充/代理、组数 ≥500 的用户收到 HTTP 431 的回归(Go 1.26 构建无此限制)。https://github.com/kubernetes/kubernetes/pull/142607
- `etcd_request_*` 指标拆分 `deleteGet` / `updateGet` 并给 error 加 `reason` 标签。https://github.com/kubernetes/kubernetes/pull/142484
- client-go 新增 consistency store,弃用 `pkg/controller` 中的 consistency。https://github.com/kubernetes/kubernetes/pull/142537
- **controller-runtime v0.25.2**(10/01):新增 metrics handler options + ReadYourWrite 一致性等待时长指标;修 `SubResourceCreateOptions.ApplyToSubResourceCreate`;文档明确 **ReadYourWrite 在 >1 namespace 下不正确**(多命名空间缓存用户注意)。https://github.com/kubernetes-sigs/controller-runtime/releases/tag/v0.25.2
- kubebuilder 跟随升级到 controller-runtime v0.25.2(机械 bump,略)。

## 值得跟进

- [ ] **IPPR 滚动策略**:读 KEP-6438 Resize Gates 设计(https://github.com/kubernetes/enhancements/pull/6459)——它决定 in-place resize 在我们产品里能否安全做"原地改规格"而不触发重建,直接影响资源效率卖点。
- [ ] **apiserver 稳定性**:评估 KEP-6268 慢 watch 流 stall/resume(https://github.com/kubernetes/enhancements/pull/6269)对我们高负载下大量 controller 的影响,1.38 是否值得为此跟进。
- [ ] **1.38 升级清单(node 侧)**:核查用 `hostUsers:false`(user namespace)的节点 `/etc/subuid`/`/etc/subgid` 配置,防止升 kubelet 后拒绝启动(https://github.com/kubernetes/kubernetes/pull/141345)。
- [ ] **Karpenter 自愈**:若产品栈用 Karpenter,评估本周 node repair / reboot-into-repair 线(https://github.com/kubernetes-sigs/karpenter/commit/1a3b9990fb034bcae8)对节点自愈策略与 SLO 的影响。
- [ ] **controller-runtime 0.25.2**:如果我们用了 ReadYourWrite 且是多 namespace 缓存,确认受"ReadYourWrite 在 >1 namespace 下不正确"影响面。
- [ ] **deep-dive 触发**:等 **1.38 rc.0** 或正式 tag 出现时,跑 `tasks/k8s-release-deep-dive.md` 做全量版本档案。
