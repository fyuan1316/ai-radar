## 调度(kube-scheduler)

通用调度侧本周期变化不大,几条值得知道的:

- **required 亲和/反亲和(topologyKey=hostname)性能优化**:大规模场景常见热点,直接改进吞吐。(1.37 Feature)
- **SchedulerPreQueueingHints 回退为 alpha**:原计划 beta 默认开,临发现问题降回 alpha。插件可提供 PreQueueingHintFn 缩小事件驱动下的重评估 Pod 集合。https://github.com/kubernetes/kubernetes/pull/140959
- **调度器指标补齐**:`scheduler_plugin_execution_duration_seconds`、`scheduling_algorithm_duration_seconds` 从 alpha 升 beta;新增 client-go informer 指标(`informer_store_resource_version` 等,label `name=kube-scheduler`),便于观测调度器自身 informer 压力。https://github.com/kubernetes/kubernetes/pull/140511
- 注:1.37 调度器大头是 Workload-Aware Scheduling / PodGroup gang / DRA 相关(Workload、PodGroup 升 scheduling.k8s.io/v1beta1,workload-aware preemption 等)——**这些归 k8s-ai-infra,本任务不展开**。仅提示升级注意:从 1.36 升 1.37 前需删除所有 `scheduling.k8s.io/v1alpha2` 的 Workload/PodGroup 对象。https://github.com/kubernetes/kubernetes/pull/140184

## 节点 & kubelet

本周期节点侧动作最多,几条对我们产品直接相关:

- **EvictionRequest / evictionResponders(alpha,新增 Pod 字段 + EvictionRequest 资源)**:一组 requester/responder 协调 Pod 的优雅驱逐。对我们做「模型服务优雅下线 / 有状态推理 Pod 驱逐编排」是可对接的原生机制,值得跟。https://github.com/kubernetes/kubernetes/pull/137050
- **MemoryQoS 转 beta**:memory.high 不再默认强加(默认 nil),避免对内存敏感负载(推理进程)误伤;同时修了 in-place resize 时 pod 级 memory.min/low 被静默丢弃的 bug。https://github.com/kubernetes/kubernetes/pull/140007
- **DefaultPodSysctls(alpha)**:kubelet 配置项 `DefaultPodSysctls`,给 Linux 节点上所有 Pod 设默认 sysctl(off by default)。https://github.com/kubernetes/kubernetes/pull/140052
- **gRPC 探针支持 TLS(KEP-4939)+ HTTP/2 cleartext(H2C)探针**:探针能力补齐,mTLS 环境下的健康检查更顺。https://github.com/kubernetes/kubernetes/pull/137762
- **KubeletInUserNamespace 转 beta(KEP-2033)**:rootless kubelet 更近一步,对多租户隔离有意义。https://github.com/kubernetes/kubernetes/pull/134639
- **Kubelet PodsAPI gRPC 服务转 beta**;新增 `allocatedPods` endpoint(gate `KubeletAllocatedPodsEndpoint`)暴露已分配 Pod spec,专门用于排查 in-place resize。https://github.com/kubernetes/kubernetes/pull/140286
- 卷/挂载细化:emptyDir 可设目录 mode 权限位;per-container 挂载可指定 `noexec/nodev/nosuid`——安全基线加固的抓手。https://github.com/kubernetes/kubernetes/pull/140013
- 稳定性修复:修了 1.35 回归(优雅终止时 exec readiness 探针停摆导致 Ready 冻结)。https://github.com/kubernetes/kubernetes/pull/140882

## 自动扩缩容(VPA / CA / Karpenter)

- **In-place resize 线(本任务重点跟踪)**:
  - `InPlacePodVerticalScalingInitContainers` **GA** —— init 容器也支持原地竖直扩缩。https://github.com/kubernetes/kubernetes/pull/140728
  - `InPlacePodVerticalScalingMemoryBackedVolumes` **alpha** —— 支持动态调整 memory-backed 卷大小(原地 resize 的一块拼图)。https://github.com/kubernetes/kubernetes/pull/139425
  - 新增可观测:`kubelet_pod_deferred_resize_duration_seconds`、`pod_pending_resizes` 加 `priority_bucket` label。
  - 判断:in-place pod resize 主体 1.33 已 GA,1.37 继续补 init 容器/内存卷/可观测,**VPA 走 in-place 后端在生产可用度进一步提升**;但 VPA 仓库本窗口无新 release(最近 `vertical-pod-autoscaler-1.7.1` 是 7/25,窗口外)。
- **HPA**:
  - **KEP-4951 可配置 tolerance 升 stable/GA** —— 允许按 HPA 设扩缩容触发容差,减少抖动,生产可用。https://github.com/kubernetes/enhancements/issues/4951
  - 新 KEP-6003:给 HPA spec 加 `syncPeriodSeconds`,支持 per-HPA 覆盖全局同步周期(当前只能全局 `--horizontal-pod-autoscaler-sync-period`)。https://github.com/kubernetes/enhancements/pull/6004
  - KEP-5679 新增 fallback 策略字段(Static / UseMax / UseMin)—— metrics 不可用时的兜底行为,对 GPU 指标源不稳的推理 HPA 有用。https://github.com/kubernetes/enhancements/pull/6213
- **Cluster Autoscaler / Karpenter / cluster-api**:本窗口均无新 release(Karpenter `v1.14.0`=7/10,cluster-api `v1.14.0` GA=7/30,均窗口外)。无重大更新。

## API Machinery & Operator 生态

- **WatchCacheStallResume(新 KEP-6268,alpha)**:慢/卡住的 watch 客户端不再拖累或被强杀,而是从 watch cache 历史「挂起-恢复」。对大规模集群 apiserver 稳定性是实打实的改善,值得读。https://github.com/kubernetes/enhancements/pull/6269
- **EtcdRangeStream 转 beta 默认开**:etcd range 流式读,降 apiserver list 内存峰值。https://github.com/kubernetes/kubernetes/pull/140085
- **ManifestBasedAdmissionControlConfig 转 beta**;`ExcludeAdmissionWebhookVirtualResources` beta 默认开(admission webhook 跳过 tokenreviews/subjectaccessreviews 等虚拟资源,减无谓调用)。https://github.com/kubernetes/kubernetes/pull/140019
- client-go:大范围移除 `context.TODO`,改由调用方传 context/logger——升级依赖 client-go 的 operator 时留意编译面变化。https://github.com/kubernetes/kubernetes/pull/129125
- 不安全对象删除(corrupt object deletion)支持 dry-run。https://github.com/kubernetes/kubernetes/pull/134037
- **controller-runtime / kubebuilder / operator-sdk**:本窗口无新 release(controller-runtime 稳定在 `v0.24.1`=5/11)。无重大更新。

## 网络 & 存储(大盘)

- **kube-proxy nftables 提速**:`NFTablesNetlink` beta 默认开——直接用 netlink 列规则/链,不再 fork `nft` 命令解析,大规模 Service 场景性能改善。https://github.com/kubernetes/kubernetes/pull/137536
- nftables 模式可选启用 userspace TCP proxy,支持 IPv4/IPv6 的 localhost NodePort。https://github.com/kubernetes/kubernetes/pull/138427
- **Service External Failover Policy(新 KEP-6272,provisional)**:给 `externalTrafficPolicy: Local` 的 Service 加 `spec.externalFailoverPolicy: Passthrough`,本地无可用 endpoint 时让流量走常规路由兜底而非直接丢包(BGP/DSR 场景)。https://github.com/kubernetes/enhancements/pull/6273
- **Cilium 补丁**:`v1.20.1 / v1.19.7 / v1.18.13`(8/18)——clustermesh 文档重构、DSR Service 断连恢复提速、一批 bugfix,维护性 backport,无新特性。https://github.com/cilium/cilium/releases/tag/v1.20.1
- Gateway API / Calico / CSI sidecar(external-provisioner/snapshotter/attacher):本窗口无新 release。存储侧 1.37 内有卷健康上报 API(alpha)与「无 CSI driver 节点阻止调度」转 beta。https://github.com/kubernetes/kubernetes/pull/140612
