# K8s AI 基础设施周报 2026-10-15

> 窗口:2026-10-08 ~ 2026-10-15。数据源:GitHub API(releases + merged PR + sig/scheduling label + enhancements KEP)。

## 摘要(3 条以内)

1. **上游原生 gang 本周密集落地,JobSet 带头"投靠" WAS**:kube-scheduler 的 CompositePodGroup(CPG)一周合并近 10 个 PR(运行时层级校验、系统 PriorityClass 支持、抢占业务逻辑拆分、CPG 抢占指标、PreEnqueue 性能),同时 **JobSet v0.13.0 新增 alpha `spec.scheduling`**,直接生成 Workload+PodGroup 交给上游 WAS 调度——这是 v1.36 PodGroup API / 原子成组调度周期从"API 落地"走向"编排层接入"的分水岭,对 Volcano 的 gang 独占性是实打实的稀释。
2. **Volcano v1.16.0 是个大版本,但重心明显上移到"上游不碰的地盘"**:NamespaceQueue(命名空间级分层队列/租户自治)、fairshare 插件(Slurm 式历史用量衰减)、PodGroup 拓扑反亲和、**HyperNode 控制器独立可部署(拓扑发现 API 开放给其他调度器复用)**、DRA 打分、K8s 1.36 支持、HAMi 昇腾软切分(vNPU)。同时修了一个 DRA 配额计数的 DoS 安全漏洞(GHSA,CVSS 6.5)。
3. **DRA 新 KEP-5981「Sharing Affinity for Consumable Capacity」值得盯**:在 KEP-5075 可消费容量(定量)之上补"定性模态锁"——部分分配的共享设备(RDMA 网卡/FPGA/多租户 GPU)一旦锁到某配置模式(子网/分区键/bitstream)后,调度器如何安全复用。这是 DRA 从"切显存/算力"向"切带状态的硬件功能"演进的信号。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

本周 sig/scheduling 合并 PR 几乎全是 CompositePodGroup(CPG,即 KEP-4671 Workload API gang 的 v1.36 实现)收尾:

- **Allow system priority classes on PodGroups** — PodGroup 现在允许挂 `system-*` 高优先级类,向系统关键负载的 gang 调度打通。https://github.com/kubernetes/kubernetes/pull/142846
- **Validate pod group runtime hierarchies in kube-scheduler** — 调度周期内强校验 PodGroup 层级(含 CPG 抢占集成测试修复),原子成组调度周期的正确性护栏。https://github.com/kubernetes/kubernetes/pull/142719
- **scheduler: use successfulLeafResults in PodGroupSchedulingFunc** — 修复 CPG 层级下 map 遍历导致 ProposedAssignments 不确定的两个 bug。https://github.com/kubernetes/kubernetes/pull/142979
- **Improve performance of PreEnqueue for CompositePodGroups** — 把 CPG 就绪判断从 `O(pods × 层级)` 的按需遍历降下来(`wg/workload-aware-scheduling`)。https://github.com/kubernetes/kubernetes/pull/141030
- **support CompositePodGroup in workload preemption metrics** / **Move preemption business logic out of types.go** — 抢占路径为 CPG 重构、补指标,铺 KEP-5710(workload-aware preemption)。https://github.com/kubernetes/kubernetes/pull/141969 https://github.com/kubernetes/kubernetes/pull/142946
- **[WAS] scheduler-perf baseline + draft SLOs for TAS placement limit** — 为 TAS(KEP-5732)放置上限建性能基线与草案 SLO。https://github.com/kubernetes/kubernetes/pull/140611

**WAS vs 生态调度器研判(本期)**:这一波 CPG 收尾 + JobSet 原生接 WAS,是上游第一次把"编排层直接产 Workload/PodGroup 给 kube-scheduler"跑通——**挤压的是 Volcano/Kueue 的基础 gang 原语地盘**(以前"要 gang 就得上 Volcano"的理由在变弱)。反过来看 Volcano v1.16 的动作(租户自治队列、历史公平、拓扑反亲和、HyperNode API 开放、加速器软切分)全在上游短期不会碰的上层,**生态调度器正主动向"上游 gang 之上的差异化能力"撤退**;且 Grove、KubeRay 本周都选了 Volcano 作为多级 gang 后端(见下),说明"复杂多角色 AI 负载的 gang"短期仍是生态调度器的护城河。

### Volcano / Kthena

**Volcano v1.16.0**(2026-10-14,大版本):https://github.com/volcano-sh/volcano/releases/tag/v1.16.0

- **NamespaceQueue(命名空间级分层队列)**:`scheduling.volcano.sh/v1beta1` 新 CRD,租户在自己 namespace 内建父子队列/配额,管理员通过 cluster Queue `spec.allowedNamespaces` 授权;默认关,仅 capacity 插件支持,默认 5 层。对标"多租户自治"刚需。https://github.com/volcano-sh/volcano/pull/5590
- **fairshare 插件**:Slurm 式累计 resource-seconds + 指数半衰(默认 4h),解决"同队列多 namespace 共享、连续提 GPU 作业者反复抢占优先级"的长期公平问题;需排在 drf 前。https://github.com/volcano-sh/volcano/pull/5161
- **PodGroup 拓扑反亲和**:`spec.topologyAffinity.podGroupAntiAffinity`,按 HyperNode tier 把不同推理副本打散到不同 supernode,避开共享故障域。https://github.com/volcano-sh/volcano/pull/5349
- **HyperNode 控制器独立可部署**:拓扑发现(UFM/节点标签)+ supernode 管理独立成 `vc-hypernode-controller-manager`,**其他调度器可通过 HyperNode API 复用拓扑**——Volcano 把拓扑层做成了可被上游/友商消费的基础设施。https://github.com/volcano-sh/volcano/pull/5137
- **DRA 打分 + DRA 安全修复**:对优先设备请求应用上游 DynamicResources Score/NormalizeScore(#5728);修 **GHSA-j38h-7pfq-cxmw**——租户可控的设备/最小任务计数触发 DRA 容量聚合在调度器缓存锁下的过度迭代,阻塞跨命名空间调度(CVSS 6.5 Medium,`DRAConsumableCapacity` 默认关),已以常数时间 Quantity 乘法 + 溢出守卫修复。https://github.com/volcano-sh/volcano/security/advisories/GHSA-j38h-7pfq-cxmw
- **其他**:UnschedulableJobCache(不可调度作业缓存,事件驱动唤醒,默认关)、usage 插件批量派发负载估计、队列按 nodegroup 配额、K8s 1.36 支持(Go 1.26)、用上游 VolumeBinding 替换自家 fork。
- **生态**:Grove(#516)与 KubeRay(#5249)本周均合并 Volcano 多级 gang 后端——角色映射到 PodGroup SubGroup,支持角色级 gang 约束(多机副本)。https://github.com/volcano-sh/volcano/releases/tag/v1.16.0

**Kthena**(本周无 release,活跃 PR):ModelServing 新增驱逐保护(#1485)、提出版本历史与回滚(#1607)、router 修 sticky session 并发关闭与负分权重拒绝、autoscaler 对齐 vLLM KV-cache 指标系列。推理调度/路由侧持续补企业级稳定性,和 KServe/InferNex 同赛道值得继续跟。https://github.com/volcano-sh/kthena/pull/1485

### DRA

- **KEP-5981 DRA Sharing Affinity for Consumable Capacity**(enhancements PR #5987):在 KEP-5075 可消费容量(定量切分)之上补**定性模态锁**——部分分配的设备锁定某模式(子网/分区键/bitstream 等,典型 RDMA 网卡/FPGA/多租户 GPU)后,调度器凭"sharing affinity"安全复用同模式的剩余容量。DRA 正从"切显存/算力数字"扩到"切带配置状态的硬件功能"。https://github.com/kubernetes/enhancements/issues/5981
- **Volcano DRA 配额**:计数配额用饱和算术防溢出(#5621)、容量缩放用常数时间 Quantity 乘法防调度器卡死(见安全修复)。
- **Kueue DRA**:requeue Workload 按当前 generation 配对配额(见 Kueue 段)。
- dra-evolution / scheduler-plugins 本周无 merged PR。

### LWS / JobSet

**JobSet v0.13.0**(2026-10-12):https://github.com/kubernetes-sigs/jobset/releases/tag/v0.13.0

- **alpha Workload-Aware Scheduling 集成**(`JobSetWorkloadAwareSchedulingAPI` gate,默认关):新增 `spec.scheduling` 支持整 JobSet / ReplicatedJob 组 / 单 Job 副本级的 Basic 或 Gang 调度;**自动创建并协调 Workload 及其 PodGroups**、通过 `schedulingGroup.podGroupName` 映射子 Pod、给 Job 打 `scheduling.k8s.io/group-template-name`;支持通过 `resourceClaims` 共享 DRA 声明(alpha 不含复合 PodGroup 层级)。**这是编排层直接产 Workload 交 kube-scheduler 的第一个实例**。https://github.com/kubernetes-sigs/jobset/pull/1250

**LWS DisaggregatedSet**(本周无 release,PR 大量硬化):P/D 分离的核心 workload——本周集中修 rollout(`maxUnavailable=100%` 支持 #1181、scale-from-zero #1182、informer-only 观测 #1172)、admission 校验(拒绝非法子配置 #1176 / 重复角色 #1175 / 过期 group policy #1174)、cleanup 不误删无关对象(#1177);另加 controller 的 PDB(#1187)。OAI 已在用 LWS,DisaggregatedSet 正快速逼近生产可用,和生态侧 KServe DisaggregatedSet / Dynamo Grove 是同一 P/D 下沉编排层趋势。https://github.com/kubernetes-sigs/lws/pull/1182

## KEP 动向

- **KEP-5981 DRA Sharing Affinity for Consumable Capacity**(新):定性模态锁下的共享设备复用,补 KEP-5075 短板。https://github.com/kubernetes/enhancements/issues/5981
