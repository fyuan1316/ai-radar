# K8s AI 基础设施周报 2026-09-03

窗口:2026-08-27 → 2026-09-03

## 摘要(3 条以内)

1. **Kueue 亮出新护城河:Dynamic Quota Orchestration(KEP-12382)首批 v1beta2 API 落地**。本周合入 `DynamicQuotaOrchestrator` API([#14557](https://github.com/kubernetes-sigs/kueue/pull/14557))与给 ClusterQueue/Cohort 加 `status.effectiveQuotas` 字段([#14389](https://github.com/kubernetes-sigs/kueue/pull/14389),alpha),配额不再是静态配置而是由"编排器"动态计算并写回有效配额。叠加 PartialScaleUp for ElasticJobs KEP([#14310](https://github.com/kubernetes-sigs/kueue/pull/14310))——配额不足时弹性作业按 `minCount` 先起小再扩。**研判信号**:上游把 gang 原语收编得越狠,Kueue 越往"动态配额/公平/弹性"这层厚护城河上加码,这块地上游短期不会碰。

2. **上游原生 gang 进入 v1.38 深水区:CompositePodGroup(CPG)成型 + GangScheduling 插件重构**。k/k 本周把 PodGroup 与 CompositePodGroup 在 `workloadForest` 里统一([#141081](https://github.com/kubernetes/kubernetes/pull/141081)),调度队列改为**逐 entity** 跑 PreEnqueue([#141575](https://github.com/kubernetes/kubernetes/pull/141575)/[#141577](https://github.com/kubernetes/kubernetes/pull/141577)),并**从 GangScheduling 插件里移除 Permit 机制**([#141182](https://github.com/kubernetes/kubernetes/pull/141182))——原生成组调度不再靠 Permit 阻塞点,而是走 workload 感知的成组周期。这是 `GenericWorkload` beta(v1.37)之后把 gang 语义做成"多 PodGroup 可组合(composite)"的架构演进。

3. **DRA 主线转入 v1.38 毕业筹备**:`ResourcePoolStatus`(KEP-5677)瞄准 **v1.38 beta**([#6301](https://github.com/kubernetes/enhancements/pull/6301)),新 KEP-6080 **DRA Derived Attributes**(派生属性,[#6255](https://github.com/kubernetes/enhancements/pull/6255))进入视野;k/k 修复 `DRANodeAllocatableResources` 开启时扩展资源的计算([#141556](https://github.com/kubernetes/kubernetes/pull/141556))。gpu-operator v26.7.0 GA 之后本周转入观测/清理期,无新 DRA 方向。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

本周 k/k sig/scheduling 合入约 30 条,主线全压在 **CompositePodGroup(CPG)** 与 GangScheduling 插件重构上:

- ⭐ **[#141081 在 workloadForest 里统一 PodGroup 与 CompositePodGroup 的代码](https://github.com/kubernetes/kubernetes/pull/141081)**——把"单 PodGroup"和"可组合的复合 PodGroup"收敛到同一套 workload 森林数据结构,是原生 gang 从"单组"走向"多组可组合"的地基。
- ⭐ **[#141182 从 GangScheduling 插件移除 Permit 支持](https://github.com/kubernetes/kubernetes/pull/141182)**——原生成组调度不再依赖 Permit 阻塞等待,改由 workload-aware 的成组调度周期驱动。这与生态调度器(Volcano)靠 Permit/session 攒够再一起放的经典 gang 实现分道扬镳。
- **逐 entity 调度队列**:[#141575 每个 entity 独立跑 PreEnqueueCheck](https://github.com/kubernetes/kubernetes/pull/141575) + [#141577 pod group 内首个被 gated 的 pod 之后停跑 PreEnqueue 插件](https://github.com/kubernetes/kubernetes/pull/141577) + [#141546 ForEachPodInfo 改 iter.Seq](https://github.com/kubernetes/kubernetes/pull/141546)——调度队列被改造成"以 workload/entity 为单位"而非纯 pod 粒度。
- **测试面在补齐**(feature 冲 beta 前置工):[#141331 pod group 与独立 pod 交错调度的集成测试](https://github.com/kubernetes/kubernetes/pull/141331)、[#141409 CPG 开/关两态跑独立 pod group 集成测试](https://github.com/kubernetes/kubernetes/pull/141409)、[#140835 CPG feature gate 开启下跑既有 PG scheduler_perf](https://github.com/kubernetes/kubernetes/pull/140835)。
- **抢占(WAP/KEP-5710)继续补洞**:[#140999 相同起始时间下 MoreImportantVictim 判定确定化](https://github.com/kubernetes/kubernetes/pull/140999)、[#140872 修 workload-aware preemption 按命名空间扩展资源的 flake](https://github.com/kubernetes/kubernetes/pull/140872)。
- **GA 清理**:[#141741 移除 `PodSchedulingReadiness` feature gate(v1.30 已 GA 锁定,action required)](https://github.com/kubernetes/kubernetes/pull/141741)——scheduling gates 机制彻底转正,这是 WAS/gang 依赖的"起跑前置门"底座。
- **DRA 交叉修复**:[#141556 `DRANodeAllocatableResources` 开启时修扩展资源计算](https://github.com/kubernetes/kubernetes/pull/141556)。

**常设研判(WAS 原生化 vs 生态调度器)**:本周分工比上周更清晰——**上游啃"gang 原语 + 成组调度周期"(CPG/移除 Permit),Kueue 转身加固"动态配额/弹性"(见下)**。即上游把"要 gang 就得上 Volcano/Coscheduling 的 Permit 攒批"这套挤掉,而生态项目主动上移到配额/公平/弹性/拓扑这层。选型结论不变并强化:**押"能干净跑在原生 CPG/Workload 之上、且在配额弹性层有厚度"的调度器(Kueue 路线)**;纯 Permit 式 gang 插件(薄 coscheduling)的长期空间继续被压缩。

### Kueue

本周是全期最活跃仓,方向是**新配额编排 API**:

- ⭐ **[#14557 新增 `DynamicQuotaOrchestrator` API](https://github.com/kubernetes-sigs/kueue/pull/14557)** + **[#14389 ClusterQueue/Cohort 加 `status.effectiveQuotas`(v1beta2,alpha)](https://github.com/kubernetes-sigs/kueue/pull/14389)**——同属 **KEP-12382 Dynamic Quota Orchestration**。配额从"静态 nominalQuota 配置"升级为"由编排器动态计算有效配额并写回 status",为跨 Cohort 的动态借还/再分配打底。**对我们**:多租户 GPU 配额如果还在用静态配额 + 人工调,这是要重点跟的能力面;它把"配额编排"做成可插拔 API,是 Kueue 区别于纯调度器的核心差异化。
- ⭐ **[#14310 KEP:ElasticJobs 的 PartialScaleUp](https://github.com/kubernetes-sigs/kueue/pull/14310)**——配额不足时弹性作业(含 Ray)按组件 `minCount` 先起小,容量释放后再扩;记录多组件已 admit 计数。弹性训练/推理在配额紧张集群里的关键调度语义。
- **WAS 集成推进**:[#15025 WAS Integration 模拟器实现清理](https://github.com/kubernetes-sigs/kueue/pull/15025) + [#14794 更新调度器快照模拟器以支持模拟执行](https://github.com/kubernetes-sigs/kueue/pull/14794)——Kueue 在把上游 scheduler-library 的仿真能力接进来(承接上期 `SchedulerLibraryIntegration`)。
- **DRA 配额继续对齐**:[#14436 PodSet 相等性判断纳入 pod 级 Resources 与 ResourceClaims](https://github.com/kubernetes-sigs/kueue/pull/14436)——DRA/pod-level 资源在配额去重上的正确性,印证"DRA 配额路径实战修洞期"仍在。
- **安全/记账**:[#14863 抢占失败时清除粘滞的 preemptorWorkload](https://github.com/kubernetes-sigs/kueue/pull/14863)、[#14997 MultiKueue 远端 OwnerNotFound 结束时重置 admission check 而非直接结束管理侧 workload](https://github.com/kubernetes-sigs/kueue/pull/14997)、[#14585 TAS 拒绝拓扑请求不匹配的预建 Workload](https://github.com/kubernetes-sigs/kueue/pull/14585)。
- **性能**:一组"调度等价哈希只算一次/避免冗余计算"的重构([#14958](https://github.com/kubernetes-sigs/kueue/pull/14958)/[#15050](https://github.com/kubernetes-sigs/kueue/pull/15050)/[#14889](https://github.com/kubernetes-sigs/kueue/pull/14889))——大规模队列的调度吞吐优化。
- **Ray**:[#14670 支持 KubeRay v1.7 History Server collectors](https://github.com/kubernetes-sigs/kueue/pull/14670)。
- 启示:**生产多租户配额把 Dynamic Quota Orchestration(KEP-12382)列入路线跟踪**;弹性作业场景关注 PartialScaleUp 的 GA 节奏。

### LWS / JobSet

- ⭐ **LWS 落地 KEP-898 Hash 组身份**:[#987 新增 `spec.groupIdentity` 的 `Hash` 模式,leader 由 Deployment(而非 StatefulSet)托管](https://github.com/kubernetes-sigs/lws/pull/987)——Hash 模式下组用 40 位随机 key 标识、leader pod 带 `group-ready` 就绪门控整组灰度、缩容优先删未就绪组(ReplicaSet 式受害者排序)、worker 走 leader Pod IP(`LWS_LEADER_ADDRESS`)。DisaggregatedSet 各角色可在内联 LWS spec 里选择启用。**含义**:多节点推理/训练组的身份从"有序序号(StatefulSet)"松绑为"哈希 + Deployment",更契合弹性/滚动更新——是 OAI 已在用的 LWS 的一次实质架构增强。配套:[#1017 role label 只打在 StatefulSet metadata 不进 pod template](https://github.com/kubernetes-sigs/lws/pull/1017)、[#999 修 RecreateGroupOnPodRestart 删除竞态](https://github.com/kubernetes-sigs/lws/pull/999)、[#953 Helm 同步扩展到 CRD 之外](https://github.com/kubernetes-sigs/lws/pull/953)。
