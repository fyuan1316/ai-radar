## K8s 核心版本节奏

- Kubernetes 四支维护分支同日发补丁 [v1.37.1](https://github.com/kubernetes/kubernetes/releases/tag/v1.37.1) / [v1.36.5](https://github.com/kubernetes/kubernetes/releases/tag/v1.36.5) / [v1.35.9](https://github.com/kubernetes/kubernetes/releases/tag/v1.35.9) / [v1.34.12](https://github.com/kubernetes/kubernetes/releases/tag/v1.34.12)。1.37.1 关键修复:
  - kube-scheduler DRA 分配器:ResourceClaim 设备请求数溢出 int 不再崩溃调度器、不再跳过 `firstAvailable` 回退([#141922](https://github.com/kubernetes/kubernetes/pull/141922))。
  - [#141998](https://github.com/kubernetes/kubernetes/pull/141998):无 `deviceSelector` 的 DeviceTaintRule 曾误匹配全集群设备、把所有 DRA 设备打成不可调度,现修正为不匹配任何设备。
  - kubeadm 不再把节点专属 systemd-resolved 的 resolvConf 路径写进集群级 kubelet-config ConfigMap([#141627](https://github.com/kubernetes/kubernetes/pull/141627))。
  - 启示:前两条虽落在 DRA(AI 侧),但都是**补丁级 scheduler 稳定性/可调度性**修复,任何用 ResourceClaim/设备污点的集群都会踩,应纳入升级基线;kubeadm 那条影响多节点集群一致性,自动化部署需回归。
- 1.38 处于 enhancements freeze 窗口(大批 KEP 定 1.38 里程碑),但**尚无 rc.0 / 正式 tag**,deep-dive 版本档案暂不需要跑;详见下方"KEP 动向"与"值得跟进"。

## 调度(kube-scheduler)

- [KEP-5598 Rescore extension point](https://github.com/kubernetes/enhancements/pull/6411) — 调度框架新增通用 rescore 扩展点,允许在 Score 之后按新扩展点重打分。
  - 启示:这是**通用**调度框架能力,不限 AI。我们若做自定义打分/重排(如按成本、拓扑二次打分),未来应对齐这个官方扩展点而不是私改 scheduler。
- [KEP-5836 Scheduler preemption for IPPR(in-place pod resize)beta](https://github.com/kubernetes/enhancements/pull/6344) — 为 in-place pod resize 场景补抢占语义,推进 1.38 beta。
  - 启示:in-place resize 与抢占的交互开始进核心。配合 VPA in-place,资源紧张时"就地扩容 vs 抢占"会成为真实策略点,做资源超卖/QoS 时要提前想清楚。

## 节点 & kubelet

- [KEP-6416 Kubelet Parallel Container Operations](https://github.com/kubernetes/enhancements/pull/6419) — kubelet 并行化容器操作(创建/启动)。
  - 启示:高密度节点(多容器 Pod、sidecar 多)启动延迟有望下降,对推理 Pod 冷启动、批任务大规模并发拉起是正向;需跟 CRI runtime 版本联动验证。
- [KEP-6249 发布 Graceful Node Shutdown 状态供 DaemonSet 协调](https://github.com/kubernetes/enhancements/pull/6351) — 节点优雅关机状态对外暴露,DaemonSet 可据此协调。
  - 启示:节点下线时日志/监控/存储类 DaemonSet 能做有序收尾,对我们平台的可观测 agent、CSI node plugin 退出顺序有用。
- [KEP-6122 CPU Configurable Scaling Delay(alpha 1.38)](https://github.com/kubernetes/enhancements/pull/6314) 与 [KEP-5894 Node system partition(alpha 1.38)](https://github.com/kubernetes/enhancements/pull/6387) — 前者可配置 CPU 频率/缩放延迟,后者为系统组件划独立分区。
  - 启示:两条都朝"节点资源更细粒度隔离"走,和我们做 GPU/NPU 节点系统预留、避免系统进程与 workload 争抢相关。
- [KEP-6030 Dynamic resize of memory-backed volumes(beta)](https://github.com/kubernetes/enhancements/pull/6320) — memory-backed emptyDir 动态扩缩推进 beta。
  - 启示:训练/推理常用 emptyDir(shm)做数据缓冲,动态调整避免重建 Pod,值得跟进。

## 自动扩缩容(VPA / CA / Karpenter)

- [VPA 1.8.0](https://github.com/kubernetes/autoscaler/releases/tag/vertical-pod-autoscaler-1.8.0)(含 [chart 0.13.0](https://github.com/kubernetes/autoscaler/releases/tag/vertical-pod-autoscaler-chart-0.13.0))发布,in-place 相关持续打磨:
  - reactive CPU startup boost 的"回退/unboost"([#10087](https://github.com/kubernetes/autoscaler/pull/10087));新增 `inplace_cache_pods_total` 指标统计因 infeasible 缓存被跳过的 in-place 更新([#9819](https://github.com/kubernetes/autoscaler/pull/9819));`controlledResources` 字段加校验([#9951](https://github.com/kubernetes/autoscaler/pull/9951))。
  - 同期 [VPA 1.7.2](https://github.com/kubernetes/autoscaler/releases/tag/vertical-pod-autoscaler-1.7.2):in-place 遇到瞬时 kubelet ResizeError 时按 deferred 处理、不再永久判死([#10104](https://github.com/kubernetes/autoscaler/pull/10104))。
  - 启示:这条正是任务盯的主线——**in-place pod resize 落地后 VPA 才在生产真正可用**。1.8.0/1.7.2 都在补 in-place 的边界条件(缓存、瞬时错误、启动 boost),说明社区正把 VPA in-place 从"能跑"推向"敢上生产"。我们若要给客户提供纵向弹性,应基于 VPA 1.8+ 且 K8s 侧 in-place resize 特性门控就绪来验证。
- [Cluster Autoscaler externalgrpc 增加 resource slices 支持](https://github.com/kubernetes/autoscaler/pull/10303) — CA 的 externalgrpc cloud provider 协议扩展。
  - 启示:CA 与 DRA/资源切片的对接在补齐,自定义云 provider 接 CA 时可传更细的资源信息。
- Karpenter 本窗口无实质能力变更(仅噪声)。

## API Machinery & Operator 生态

- [KEP-3157 WatchList Promote to GA in 1.38](https://github.com/kubernetes/enhancements/pull/6388)(已合)—— streaming list(WatchList)转 GA。
  - 启示:大规模 list 场景(informer 初始同步)内存与 apiserver 压力显著下降,对我们运行大量 controller/operator 的管理面是**实打实的稳定性红利**;升级到 1.38 后应确认 client-go / controller-runtime 默认走 WatchList。
- [KEP-5866 Server-side Sharded List and Watch(beta 1.38)](https://github.com/kubernetes/enhancements/pull/6385) 与 [KEP-6268 Stall and resume slow watch streams](https://github.com/kubernetes/enhancements/pull/6269) / [KEP-6404 improve apiserver write throughput](https://github.com/kubernetes/enhancements/pull/6407) — apiserver 读写扩展性一组 KEP。
  - 启示:apiserver 可扩展性是我们大集群的天花板,这三条(分片 list/watch、慢 watch 不再直接断流、写吞吐)值得整体跟踪,决定单集群能撑多少 controller。
- [KEP-6361 Controller Leader Election Recovery](https://github.com/kubernetes/enhancements/pull/6365) — leader 选举恢复机制改进。
  - 启示:我们自家 operator/controller 大量依赖 leader election,恢复语义变化要对齐,避免升级后出现双主/空窗。
- [KEP-5793 configurable mutating webhook merge order](https://github.com/kubernetes/enhancements/pull/6417)(已合)—— 可配置 mutating webhook 的合并顺序。
  - 启示:多个 webhook(我们 + Kyverno + istio 等)相互改字段时顺序可控,减少 patch 冲突;做注入类 webhook 时可利用。
- [controller-runtime #3594](https://github.com/kubernetes-sigs/controller-runtime/pull/3594)(metrics handler options)、[#3597](https://github.com/kubernetes-sigs/controller-runtime/pull/3597)、[#3598 修复 SubResourceCreateOptions.ApplyToSubResourceCreate](https://github.com/kubernetes-sigs/controller-runtime/pull/3598) — 常规能力/修复。
- [Cluster API #14092 ClusterClass without template objects](https://github.com/kubernetes-sigs/cluster-api/pull/14092) 合入,并有 [#14258 KCP 删除时按 etcd member 匹配 machine](https://github.com/kubernetes-sigs/cluster-api/pull/14258) 修复。
  - 启示:CAPI 在简化 ClusterClass 模板与提升 etcd/control-plane 删除鲁棒性;基于 CAPI 管理节点池的客户可关注。

## 网络 & 存储(大盘)

- 网络 KEP(通用):[KEP-6032 nftables localhost nodeport proxy(beta)](https://github.com/kubernetes/enhancements/pull/6378)、[KEP-6272 Service External Failover Policy](https://github.com/kubernetes/enhancements/pull/6273)、[KEP-6313 Non Network Pods](https://github.com/kubernetes/enhancements/pull/6317)。
  - 启示:nftables kube-proxy 模式继续补齐(localhost nodeport),是 iptables 退场路线的一环;Non Network Pods 对无需网络的批任务 Pod 是减负方向。
- Gateway API:[GEP-5253 Standardized Attribute Dictionary](https://github.com/kubernetes-sigs/gateway-api/pull/5256)、[routability GEP 转 implementable](https://github.com/kubernetes-sigs/gateway-api/pull/5263),XBackend 继续修正([#5277](https://github.com/kubernetes-sigs/gateway-api/pull/5277) / [#5276](https://github.com/kubernetes-sigs/gateway-api/pull/5276)),并在准备 [1.6 release changelog](https://github.com/kubernetes-sigs/gateway-api/pull/5285)。
  - 启示:Gateway API 1.6 临近,XBackend/attribute dictionary 仍在动,做 MaaS 网关抽象要隔一层产品 API,不直接暴露上游未稳字段。
- 存储 KEP:[KEP-6395 Dynamic Node-Local Ephemeral Volumes(alpha)](https://github.com/kubernetes/enhancements/pull/6421)、[KEP-6011 CSI ControllerGetNodeInfo](https://github.com/kubernetes/enhancements/pull/6016)、[KEP-4958 CSI Sidecars All-in-one](https://github.com/kubernetes/enhancements/pull/5672)、[KEP-1979 COSI 升 v1beta1](https://github.com/kubernetes/enhancements/pull/6363)。
  - 启示:CSI sidecar 合一会简化我们存储插件的部署拓扑;COSI(对象存储接口)转 v1beta1 值得盯,模型/数据集直连对象存储是 AI 平台常见诉求。本窗口无重点 CSI provisioner/snapshotter release。

## 策略 & 安全

- [KEP-4412 Kubelet 镜像凭据 provider 用投影 SA token(GA 1.38)](https://github.com/kubernetes/enhancements/pull/6426) — kubelet 拉私有镜像的凭据从长期凭据转向短时投影 token。
  - 启示:多租户平台的镜像拉取凭据安全性提升,GA 后应作为基线;我们若自研 credential provider 需适配投影 token。
- [KEP-6061 OCI artifact-based security profile distribution](https://github.com/kubernetes/enhancements/pull/6062) 与 [KEP-6308 HTTP Message Signature Authentication(新建)](https://github.com/kubernetes/enhancements/pull/6335) — 用 OCI artifact 分发 seccomp/AppArmor profile;HTTP 消息签名认证新 KEP。
  - 启示:安全 profile 走 OCI 分发,和我们镜像/制品供应链统一,值得纳入安全基线设计。
- Gatekeeper / Kyverno 本窗口无新 release;上周(Kyverno background scan re-arm、legacy CRD keep)结论仍有效,不重复。
