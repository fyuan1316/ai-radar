# K8s 自身核心周报 2026-08-06

窗口:2026-07-30 → 2026-08-06

## 摘要(3 条以内)

1. **本周 KEP 主战场是 sig-node**:In-place Node Resource Resize(KEP-3953)时隔许久重启推进,同时冒出三个新的 kubelet 稳定性 / 大 NUMA KEP——TopologyManager `restrict-to-cpu-numa-nodes`(KEP-5726,直指 Grace Blackwell / Vera Rubin 级大 GPU 节点)、Memory Manager per-NUMA 漂移容忍(KEP-6232)、kubelet watchdog 诊断(KEP-6247)。这几条都直接落到我们大 GPU 节点的运维稳定性上。
2. **Cluster Autoscaler 正在做仓库拆分**:核心包已从 `kubernetes/autoscaler` mono-repo 迁移到独立的 `sigs.k8s.io/cluster-autoscaler`;VPA in-place resize 线继续打磨(ResizeError 改判为 deferred 而非 infeasible)。
3. **Runtime / CNI / CAPI 集中发 RC/pre**:cluster-api v1.14.0-rc.1、cilium v1.21.0-pre.0(Envoy 增量 xDS 下发降 CPU/时延)、containerd 2.4 对应的 API v1.12.0-beta.0、cri-o 三个维护分支补丁齐发。K8s 主仓本周无新 release(v1.37 处于 beta.0 之后的收尾期)。

## 节点 & kubelet

本周信号最密集的一块,四个 sig-node KEP 值得盯:

- **KEP-3953 In-place Node Resource Resize**(重启推进,updated 07-31):Pod 级 in-place resize(KEP-1287)的"节点级"类比,横跨 sig-node/scheduling/apps/autoscaling 等十余个 SIG。若落地,意味着不重建节点即可调整节点可分配资源账本,对 VPA/CA 的资源账目模型影响很大。https://github.com/kubernetes/enhancements/pull/3955
- **KEP-5726 TopologyManager `restrict-to-cpu-numa-nodes`**(updated 08-05):新增 alpha policy option,让 kubelet 在"很多无 CPU 的 NUMA 节点"的大机器上,只按"有 CPU 的 NUMA 节点"计算有效 NUMA 集并传给拓扑感知的 hint provider。KEP 明确点名 NVIDIA GraceBlackwell / VeraRubin 级平台——**这是通用 kubelet 能力,但直接决定我们大 GPU 节点上 CPU/内存/设备的拓扑对齐质量**。https://github.com/kubernetes/enhancements/pull/5992
- **KEP-6232 Memory Manager per-NUMA 内存漂移容忍**(provisional,updated 08-02):节点重启后若某 NUMA 的 `MemTotal` 因 KASLR/启动期变量发生良性小幅漂移,kubelet Static 策略当前会 crash-loop 直到人工删 checkpoint;该 KEP 提出容忍有界漂移。GPU 节点频繁重启场景的稳定性补丁。https://github.com/kubernetes/enhancements/pull/6233
- **KEP-6247 Kubelet watchdog 诊断**(新 KEP,updated 07-30):`KubeletWatchdogDiagnostics` 特性门控,在 systemd watchdog 触发重启前留下有界的健康检查/SdNotify 诊断证据。https://github.com/kubernetes/enhancements/pull/6248
- KEP-4188 修正:实现里 feature gate 落地为 `PodsAPI`(非 KEP 原名 `PodInfoAPI`),指标名也随之更新(`kubelet_pod_requests_total` 等)。https://github.com/kubernetes/enhancements/pull/6263

## 自动扩缩容(VPA / CA / Karpenter)

- **Cluster Autoscaler 仓库拆分进行中**(07-31 一批 commit):CA 的 base cloudprovider 接口、core 包、testing/reference provider 已从 `kubernetes/autoscaler` mono-repo 迁出,改为从 `sigs.k8s.io/cluster-autoscaler` 引入;autoscaler 仓内同步删除已迁移的本地包。对我们:后续跟踪 CA 要改盯新仓,打包/引用路径会变。https://github.com/kubernetes/autoscaler/pull/10002
- **VPA in-place resize 线继续打磨**:
  - "VPA InPlace: treat ResizeError as deferred, not infeasible"(08-03)——把 resize 报错从"不可行"改判为"延后重试",避免误判驱逐/放弃。https://github.com/kubernetes/autoscaler/pull/10094
  - "Improve logging visibility in CanInPlaceUpdate"(07-30)。https://github.com/kubernetes/autoscaler/pull/9968
  - 全量 VPA e2e 测试补齐(#10089)。
  - 提醒:in-place pod resize(KEP-1287)是 VPA 生产可用的关键前提,这条线仍在活跃收敛,值得持续跟。
- **Karpenter**(v1.14.0 已于上窗口发布,本窗口为 main 累积):
  - feat(metrics):disruption 指标新增 `consolidation_policy` / `termination_mode` label,扰动可观测性更细。https://github.com/kubernetes-sigs/karpenter/pull/2924
  - fix:修复 cluster state 里"未启动 nodeclaim"悬挂条目的自愈(#3190);perf:缓存 virtual pod 定义避免重复计算(#3137)。
