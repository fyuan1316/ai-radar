# K8s AI 基础设施周报 2026-09-22

窗口:2026-09-15 -> 2026-09-22(7 天)

## 摘要(3 条以内)
- Kueue 本周发布 [v0.19.5](https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.5) / [v0.18.9](https://github.com/kubernetes-sigs/kueue/releases/tag/v0.18.9)，同时合入 fair sharing refill、SparkApplication 资源预留修复、resource transformation 校验等调度公平性与集成修复。
- LWS 合入 `groupReplacementPolicy`，解决 Hash mode 下新旧 leader group 同时占容量导致满集群无法滚动的问题，说明多副本推理拓扑正在补滚动替换语义。
- Kubernetes enhancements 中 Workload Aware Scheduling Controller APIs 推进 beta，kube 主仓也出现 workload preemption 定制化、DeviceTaintRule 空 selector 告警等变化，K8s 原生批/AI 调度能力继续向核心靠拢。

## GPU / 加速器管理

- [Kubernetes PR #141831](https://github.com/kubernetes/kubernetes/pull/141831) — 对空 `DeviceTaintRule.spec.deviceSelector` 发出告警，因为该选择器会匹配所有 driver/pool/device。
  - 启示:DRA 设备污点规则的误配置影响面很大。我们的设备管理 UI/CLI 必须在用户配置“空选择器”时阻断或二次确认，避免一条规则污染全部 GPU/NPU。
- 本轮 NVIDIA `gpu-operator` / `k8s-device-plugin` 没有筛出比调度侧更高价值的 merged PR；DRA 路线主要体现在 Kueue/K8s 核心与 KServe/OAI 的集成信号中。

## 调度 & 资源分配

### Kueue

- [Kueue v0.19.5](https://github.com/kubernetes-sigs/kueue/releases/tag/v0.19.5) / [v0.18.9](https://github.com/kubernetes-sigs/kueue/releases/tag/v0.18.9) — 本周发布 patch 版本。
  - 启示:Kueue 仍处于高频修复阶段，生产引入必须跟 patch release，而不是只锁 minor。
- [Kueue PR #13729](https://github.com/kubernetes-sigs/kueue/pull/13729) — 在 `FairSharingRefill` feature gate 后加入 fair sharing refill。
  - 启示:队列公平共享不仅是 admission 排序，还涉及 quota 消耗后的补充/回填。我们做多租户 GPU/NPU 队列时，应把 fair-share debt、回填和抢占策略作为可解释指标。
- [Kueue PR #15833](https://github.com/kubernetes-sigs/kueue/pull/15833)、[#15923](https://github.com/kubernetes-sigs/kueue/pull/15923)、[#15924](https://github.com/kubernetes-sigs/kueue/pull/15924) — SparkApplication 预留 driver/executor 的 CPU 和 memory 请求，避免 Workload 少预留资源。
  - 启示:AI/数据作业的 CRD 集成不能只读一个字段。Spark、Ray、PyTorchJob、MPIJob 都需要逐一验证 PodSet 资源计算，否则 Kueue 会“看起来 admit 了”，实际节点资源被超卖。
- [Kueue PR #15926](https://github.com/kubernetes-sigs/kueue/pull/15926) — 如果 resource transformation 的 input 命中 `excludeResourcePrefixes`，直接拒绝配置。
  - 启示:资源别名/转换是 GPU/NPU 产品常见需求，但必须有强校验。否则用户以为转了 `nvidia.com/gpu`，实际因 exclude 先匹配而无效。
- [Kueue PR #15851](https://github.com/kubernetes-sigs/kueue/pull/15851) — 配置 `managedJobsNamespaceSelector` 时，默认 WorkloadPriorityClass 只作用在被管理 namespace。
  - 启示:队列控制面的 webhook 默认值必须尊重租户边界，避免给非托管项目注入默认优先级。

### LWS / JobSet

- [LWS PR #1050](https://github.com/kubernetes-sigs/lws/pull/1050) — 增加 `groupReplacementPolicy`，在 Hash mode 下串行化 group replacement，避免新 leader 在旧 group 释放容量前被调度。
  - 启示:多节点推理/训练的滚动更新不能只看 Deployment 语义。Leader-worker group 必须知道“旧组容量未释放”这个事实，否则满载集群会出现更新卡死或临时超配。
- 本轮 JobSet 未筛出同等高价值更新；Kueue Spark 集成修复更直接影响 AI/数据作业队列。

### DRA / WAS

- [KEP-6089 Workload Aware Scheduling Controller APIs](https://github.com/kubernetes/enhancements/pull/6342) — 推进 beta。
  - 启示:WAS Controller APIs 和 Kueue/LWS/JobSet 的边界值得持续跟进。它可能成为“工作负载感知调度控制面”的上游标准，影响我们未来是否自定义 PodGroup/Queue API。
- [Kubernetes PR #141932](https://github.com/kubernetes/kubernetes/pull/141932) — workload preemption 增加定制化选项。
  - 启示:抢占策略正在从简单优先级转向 workload-aware。训练任务最小运行时间、checkpoint、Gang/PodGroup 完整性应逐步进入抢占决策。
