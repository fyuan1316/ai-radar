# K8s 自身核心周报 2026-09-22

窗口:2026-09-15 -> 2026-09-22(7 天)

## 摘要(3 条以内)
- Runtime 是本周最大主线:[containerd v2.4.0](https://github.com/containerd/containerd/releases/tag/v2.4.0) 发布，CRI-O 同周发布 1.37.0/1.37.1 以及多条维护分支 patch；containerd 还修复了 unpack 阶段继承 image annotation id-mapping label 的安全/隔离风险。
- K8s 1.38 KEP 信号开始清晰:SPDY 到 WebSockets GA、CRI List Streaming beta、Workload Aware Scheduling Controller APIs beta、多个 Node/API Machinery 方向 KEP 更新。
- 网络/策略侧集中在 Gateway API/Cilium/Calico/Kyverno:Gateway API 继续补 XBackend 和 conformance，Cilium 1.20.2 等 patch 发布，Calico 把 CRD schema 校验/defaulting 与 server-side apply 补齐，Kyverno 修复后台扫描/TTL controller 瞬时错误后停摆风险。

## K8s 核心版本节奏

- [KEP-4006 Transition from SPDY to WebSockets](https://github.com/kubernetes/enhancements/pull/6364) — 标记 GA in 1.38。
  - 启示:exec/attach/port-forward 等链路的代理、中间网关和审计组件要准备 WebSocket 成为默认路径。我们集群管理面若有 API server 代理或安全审计，需要验证升级兼容性。
- [KEP-5825 CRI List Streaming](https://github.com/kubernetes/enhancements/pull/6146) — 更新 beta graduation in v1.38。
  - 启示:节点侧 list streaming 会影响 kubelet/CRI runtime 之间的大规模 pod/container 列表性能。大节点/高密度 AI worker 上，runtime 版本和 kubelet 特性门控需要联动验证。
- [KEP-6089 Workload Aware Scheduling Controller APIs](https://github.com/kubernetes/enhancements/pull/6342) — 推进 beta。
  - 启示:这条虽偏 AI/批调度，但进入核心 KEP 后会影响通用 K8s scheduling API 版图；需要和 Kueue/LWS 边界一起看。

## 调度(kube-scheduler)

- [Kubernetes PR #141932](https://github.com/kubernetes/kubernetes/pull/141932) — workload preemption 增加定制化选项。
  - 启示:抢占语义正在从 pod-level priority 走向 workload-level。我们做队列/训练平台时，应避免把抢占策略完全写在外部 controller，后续要能对齐上游核心调度器。
- [Kubernetes PR #142219](https://github.com/kubernetes/kubernetes/pull/142219) — 收敛 `QueuedPodGroupInfo.queuedPodInfos` 的导出面。
  - 启示:PodGroup / queued workload 相关内部 API 仍在变化，直接依赖 scheduler 内部结构的插件要谨慎。

## 节点 & kubelet

- [Kubernetes PR #140220](https://github.com/kubernetes/kubernetes/pull/140220) — kubelet 记录 `StaticPodURLHeader` 时只打印 key，不再打印 header values。
  - 启示:节点日志中的凭据泄露仍是现实风险。客户集群若用 static pod URL header 拉取 manifest，应将该修复纳入升级基线。
- [Kubernetes PR #140154](https://github.com/kubernetes/kubernetes/pull/140154) — 修复 kubelet `/containerLogs` 在 CRI `containerStatus` 返回错误时的 HTTP code 行为。
  - 启示:日志 API 的错误码会影响控制台、日志采集和诊断自动化。我们产品对 kubelet log endpoint 的错误处理不要只按 500/404 粗分。
- [Kubernetes PR #142018](https://github.com/kubernetes/kubernetes/pull/142018) — 移除已废弃的 `WindowsHostNetwork` feature gate。
  - 启示:Windows 节点相关历史 gate 在清理，混合 Windows/Linux 集群升级要检查旧配置残留。

## 自动扩缩容(VPA / CA / Karpenter)

- 本轮 `kubernetes/autoscaler` 和 `karpenter` 没有筛出比 Kueue/WAS 更高价值的新能力；主要关注仍应放在 Kueue、WAS、workload preemption 与节点自动扩缩容的交互。

## Runtime(containerd / CRI-O / runc)

- [containerd v2.4.0](https://github.com/containerd/containerd/releases/tag/v2.4.0) 与 [api/v1.12.0](https://github.com/containerd/containerd/releases/tag/api/v1.12.0) 发布。
  - 启示:2.4 是 2.3 LTS 后的常规特性版本，适合跟踪新能力但不应直接作为企业默认。我们的节点 runtime 支持矩阵需要区分 LTS 与 regular release。
- [containerd PR #13855](https://github.com/containerd/containerd/pull/13855) — unpack 阶段不再接受 image annotations 中的 id-mapping snapshot labels。
  - 启示:镜像 metadata 不能无条件影响 snapshotter 隔离配置。多租户 AI 平台中，用户可上传镜像，runtime 必须防止镜像 annotation 改写宿主侧 snapshot 行为。
- [containerd PR #14194](https://github.com/containerd/containerd/pull/14194) — 回滚 fetch reader EOF 关闭行为，修复 registry-cache upload retry 回归。
  - 启示:镜像/权重分发链路常依赖 registry cache 和 BuildKit。containerd 小版本变更也可能影响构建缓存和离线同步。
- [CRI-O v1.37.0](https://github.com/cri-o/cri-o/releases/tag/v1.37.0) / [v1.37.1](https://github.com/cri-o/cri-o/releases/tag/v1.37.1) 及 v1.36/v1.35/v1.34 patch 同周发布。
  - 启示:OpenShift/RHEL 路线客户会受 CRI-O 节奏影响。AI 节点镜像、GPU/NPU runtime hook、SELinux/AppArmor 组合要跟 CRI-O minor/patch 做兼容表。
- [runc PR #5458](https://github.com/opencontainers/runc/pull/5458) / [#5457](https://github.com/opencontainers/runc/pull/5457) — release-1.5 分支修复 rootfs propagation 与 sub-cgroup path check。
  - 启示:底层 runtime 修复会影响容器隔离、挂载传播和 cgroup 路径校验，尤其是有 CSI、模型缓存挂载、device plugin 注入的节点。

## API Machinery & Operator 生态

- [Kubernetes PR #141736](https://github.com/kubernetes/kubernetes/pull/141736) — 修复 client-go `MutationCache ByIndex` delete race。
  - 启示:operator/controller 高频读写缓存对象时，indexer race 可能表现为偶发 reconcile 抖动。我们的 operator 升级应包含 client-go race 修复回归。
- [Cluster API PR #14092](https://github.com/kubernetes-sigs/cluster-api/pull/14092) — ClusterClass without template objects。
  - 启示:CAPI 在降低模板对象复杂度。多集群 AI 节点池如果基于 CAPI，应关注 ClusterClass 简化后的声明式 node pool 生成方式。

## 网络 & 存储(大盘)

- [Cilium v1.20.2](https://github.com/cilium/cilium/releases/tag/v1.20.2)、[v1.19.8](https://github.com/cilium/cilium/releases/tag/v1.19.8)、[v1.18.14](https://github.com/cilium/cilium/releases/tag/v1.18.14) 发布。
  - 启示:Cilium patch 节奏依旧很快，Gateway API、hostNetwork、IPAM、DSR/MTU 修复会直接影响推理网关和多节点训练网络。
- [Cilium PR #48449](https://github.com/cilium/cilium/pull/48449) — Azure IPAM 迁移到 Multi-pool。
  - 启示:云上多池 IPAM 对弹性 AI 节点池重要，尤其是不同 node pool/租户需要不同 PodCIDR 或安全边界时。
- [Gateway API PR #5277](https://github.com/kubernetes-sigs/gateway-api/pull/5277)、[#5276](https://github.com/kubernetes-sigs/gateway-api/pull/5276) — XBackend API spec/status 继续修正。
  - 启示:XBackend 仍在演进，直接用它做生产 MaaS 后端抽象要谨慎，先隔一层产品 API。
- [Calico PR #13913](https://github.com/projectcalico/calico/pull/13913) 与 [#13872](https://github.com/projectcalico/calico/pull/13872) — 将 peer IP、network set、protocol 校验和 libcalico-go write defaults 放进 CRD schema。
  - 启示:GitOps 直接写 CRD 已是常态，不能依赖 CLI 客户端校验。我们的 CRD 也应把 defaulting/validation 下沉到 schema/webhook。
- [Calico PR #13944](https://github.com/projectcalico/calico/pull/13944) — operator 写 FelixConfiguration/BGPConfiguration 改用 server-side apply。
  - 启示:SSA managed fields 能减少 operator 与用户/GitOps 的字段 ownership 冲突。我们自有 operator 管理客户可调配置时应优先 SSA。

## 策略 & 安全

- [Kyverno PR #16288](https://github.com/kyverno/kyverno/pull/16288) — background scan 和 TTL controllers 在瞬时错误后会重新 arm，不再因 workqueue retry 耗尽而静默停止。
  - 启示:策略引擎不能静默停扫。AI 平台依赖 Kyverno/Gatekeeper 做镜像、Secret、PSA、GPU 权限策略时，要对 controller liveness 和 scan freshness 做告警。
- [Kyverno PR #17494](https://github.com/kyverno/kyverno/pull/17494) — Helm chart 为 legacy policy CRDs 加 `resource-policy keep`，防止迁移期间被 Helm prune 删除。
  - 启示:CRD 迁移存在数据丢失风险。我们做 CRD 版本升级或组件 chart 拆分时，也应对保留旧 CRD/对象给出明确策略。
- [Calico PR #13880](https://github.com/projectcalico/calico/pull/13880) — BPF connlimit 中 RST 不再释放连接槽。
  - 启示:网络策略/连接限制的边界条件会影响租户隔离。推理入口若依赖 connlimit，需跟进 CNI 实现细节。
