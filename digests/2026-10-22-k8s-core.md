# K8s 自身核心周报 2026-10-22

窗口:2026-10-15 → 2026-10-22

## 摘要(3 条以内)

1. **安静的一周,无 k8s 核心 tag**:主仓窗口内无新 release;当前稳定线 v1.37.x,开发线进到 v1.38.0-alpha.2(2026-10-07),离 rc.0 还早,deep-dive **暂不需要跑**。本周实质信号集中在 VPA / Karpenter / Cilium / Kyverno 的补丁版和 v1.38 周期的 KEP 评审。
2. **VPA 1.8.1 / 1.7.3 发布**,修了两个生产相关 bug:一是 InPlace 模式把"几天前的 OOM"误判成"刚发生的快速 OOM"(直接影响 in-place resize 线的可用性),二是 DaemonSet 副本数改用 `DesiredNumberScheduled` 而非 `NumberReady`。跟我们紧盯的 KEP-1287 in-place resize 线强相关。https://github.com/kubernetes/autoscaler/releases/tag/vertical-pod-autoscaler-1.8.1
3. **Cilium 三条稳定线同日打补丁**(1.18.15 / 1.19.9 / 1.20.3),其中一条是安全性修复:带 `nodeSelector` 的 CiliumNetworkPolicy 之前可能"静默不生效",现已修正——用 CNP 做租户隔离的要留意版本下限。https://github.com/cilium/cilium/releases/tag/v1.20.3

## 调度(kube-scheduler)

通用调度器方向本周均为 KEP 评审态,无代码 release:

- **KEP-5927 kube-scheduler 分布式追踪**:给调度器加 distributed tracing,排查"为什么这个 Pod 调度慢/调不上"的可观测性能力。对我们定位调度瓶颈有直接价值。https://github.com/kubernetes/enhancements/pull/5928
- **KEP-5869 通配符 Toleration Key**:允许 toleration 用通配符匹配 taint key,简化大面积容忍场景的配置。https://github.com/kubernetes/enhancements/pull/5880
- **KEP-6211 TopologySpread 跳过"全被 taint"的域**:计算 skew 时排除完全不可调度的拓扑域,避免因死域导致的 spread 失衡。https://github.com/kubernetes/enhancements/pull/6210

> 边界:WAS / gang / Workload API / PodGroup 等 AI 方向调度演进归 `k8s-ai-infra`,本周本任务不重复。

## 节点 & kubelet

全部为 v1.38 周期 KEP 评审,无 release:

- **KEP-6303 Windows 上的 in-place Pod 垂直伸缩(容器 resize)**:把 KEP-1287 的 in-place resize 能力扩到 Windows 节点。属 in-place resize 主线的平台补齐,和 VPA 可用性直接相关。https://github.com/kubernetes/enhancements/pull/6304
- **KEP-5986 按容器的内存压力驱逐**:eviction 粒度从 Pod 细化到 container 级的内存压力,降低"一个容器撑爆、整 Pod 被杀"的误伤。https://github.com/kubernetes/enhancements/pull/6141
- **KEP-6250 感知维护的 DaemonSet 滚动**:DaemonSet 升级时感知节点维护窗口,避免维护期打断。本周新开了实现 PR #6469。https://github.com/kubernetes/enhancements/pull/6469
- **KEP-4112 向 CRI 下传资源信息**:把 Pod 资源传到 CRI 层,持续迭代中。https://github.com/kubernetes/enhancements/pull/4113

## 自动扩缩容(VPA / CA / Karpenter)

- **VPA 1.8.1 / 1.7.3(2026-10-21,bugfix)** + helm chart 0.15.0:
  - 修 InPlace 模式把数天前的 lastState OOM 当作"刚发生的快速 OOM"处理的逻辑(#10385)——**in-place resize 线的稳定性修复,重点**。
  - DaemonSet 副本数改用 `Status.DesiredNumberScheduled`(#10373),避免 `NumberReady` 偏小导致的建议偏差。
  - Go 升到 1.26.10。
  - https://github.com/kubernetes/autoscaler/releases/tag/vertical-pod-autoscaler-1.8.1
- **Cluster Autoscaler**:窗口内无新 release。
- **Karpenter v1.14.2(2026-10-16,bugfix)**:修 NodeRepair controller 在 label 创建后才同步时的入队问题(#3366);**capacity buffer** 功能继续完善——现在会 watch scalableRef 工作负载,让预留 buffer 能正确解析(#3387)。capacity buffer 是"预留一部分 headroom 节点"的能力,值得关注其成熟度。https://github.com/kubernetes-sigs/karpenter/releases/tag/v1.14.2
- **HPA(KEP-6382,autoscaling)**:新 KEP"Per-Metric Source Routing for HPA",允许 HPA 不同指标走不同数据源路由。评审中。https://github.com/kubernetes/enhancements/pull/6391
