2. **Volcano 修复 HAMi Ascend 常规抢占**([#5843 主线](https://github.com/volcano-sh/volcano/pull/5843) + [#5866 backport release-1.15](https://github.com/volcano-sh/volcano/pull/5866)),同时 [#5869 把 DRA 容量扩缩改为 O(1)](https://github.com/volcano-sh/volcano/pull/5869) 防大容量场景卡调度。这两条直接砸在我们 HAMi + Ascend 栈上——volcano 主仓纳入数据源的第一周就捕获到强相关信号。
3. **NVIDIA k8s-device-plugin v0.20.0 发布**([release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.20.0),08-19):replicated/MIG 资源可配置 packed/distributed 分配策略、MIG `-me`/`+gfx` 后缀 profile 拆成独立资源、Rubin 架构支持。gpu-operator 主线同步批量 pin 新版本,下一个 operator release 备货中。

## GPU / 加速器管理

- [k8s-device-plugin v0.20.0](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.20.0)(08-19)要点:
  - **replicated / MIG 资源的 packed vs distributed 分配策略可配置**(#1621、#1788 打破平手时优先物理 GPU 分散)——time-slicing/MPS 共享场景下的分配形态第一次可控,做 GPU 共享产品化时这是个要暴露给用户的旋钮;
  - MIG profile 后缀(`-me`、`+me.all`、`+gfx`)拆分为独立 K8s 资源(#1807),MIG 资源命名面变宽,配额/计费侧要跟着适配;
  - Rubin 架构家族支持(#1909)、Container Toolkit 依赖升 v1.20.0、NFD chart 升 v0.19.0 且改走 OCI artifacts。
- `NVIDIA/gpu-operator` 主线本周是**发版备货模式**:pin [device-plugin v0.20.0](https://github.com/NVIDIA/gpu-operator/pull/2763)、[dra-driver-nvidia-gpu v0.5.0](https://github.com/NVIDIA/gpu-operator/pull/2762)(并[改用 NGC 正式镜像源](https://github.com/NVIDIA/gpu-operator/pull/2758))、[k8s-driver-manager v0.12.0](https://github.com/NVIDIA/gpu-operator/pull/2760)、[mig-manager v0.15.0](https://github.com/NVIDIA/gpu-operator/pull/2764)、[新驱动分支 610.57.04 / 595.91.07 / 580.178.04](https://github.com/NVIDIA/gpu-operator/pull/2750)。**dra-driver 进 operator 正式镜像面**是信号:NVIDIA 把 DRA 路径当下一版 operator 的正式组成,不再是 experimental 旁挂。
- NFD 本周无合入。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

- 本周 `kubernetes/kubernetes` sig/scheduling 仅合入 [1 条测试 flake 修复(#141336)](https://github.com/kubernetes/kubernetes/pull/141336)——1.37 冻结期,无功能流入,属正常。
- 状态锚点不变:KEP-4671 Gang Scheduling **beta 已锁进 v1.37**(上期已报),[v1.37.0-rc.1](https://github.com/kubernetes/kubernetes/releases/tag/v1.37.0-rc.1) 今日切出,距正式版一步之遥。
- **常设研判(WAS 原生化 vs 生态调度器)**:本周的对照很有意思——上游 gang 冻结待发的同时,Volcano 在忙的是 gang *之外*的护城河(HyperNode 网络拓扑、HAMi 设备共享抢占、queue 级 overcommit,见下节),Kueue 在忙配额/多集群工程化。生态项目对"原生 gang 落地"的应对姿态已经可见:**都在往 kube-scheduler 不打算做的分层上撤**,这验证了"原生 gang beta 挤压的是 scheduler-plugins Coscheduling 这类薄插件,而非 Volcano/Kueue 的厚层"的判断。

### Kueue

上周 v0.19.1 / v0.18.5 双补丁已报,本周主线是**工程化 + 双分支 backport 潮**(0.18/0.19 两条 release train 同时维护,ChatOps 发版命令一大波),实质修复挑重点:

- [DRA:配额聚合前丢弃负值 extended-resource 请求(#14654/#14655 双 backport)](https://github.com/kubernetes-sigs/kueue/pull/14655)——DRA 配额路径的又一个边界洞,印证 v0.18 DRA 默认化后进入"实战修洞期";
- [TAS:second-pass 重分配迁移目标域的账目修复(#14572)](https://github.com/kubernetes-sigs/kueue/pull/14572)——拓扑感知调度的记账正确性;
- [pod integration:拒绝按 pod group name 收养/终结外来 Workload(#13960 系列 backport)](https://github.com/kubernetes-sigs/kueue/pull/14630)——多控制器共存时的所有权安全;
- [LWS pod 补写 queue-name(#14138 backport)](https://github.com/kubernetes-sigs/kueue/pull/14603)——Kueue × LWS 集成继续打磨;
- 文档全面切 [v1beta2 API 引用(#14624)](https://github.com/kubernetes-sigs/kueue/pull/14624),v1beta1 退场进行时。

启示:Kueue 已进入"平台层软件"的运维节奏(双 LTS 分支 + 发版自动化),选型时可以按企业级依赖对待;但 DRA 配额路径仍在密集修洞,**生产开 DRA 配额建议跟 0.19.x 补丁线,别停在 .0**。

### Volcano / Kthena(新小节)

**Volcano**(本周 8 条合入,无 release):

- ⭐ [fix(deviceshare): support HAMi Ascend normal preemption(#5843)](https://github.com/volcano-sh/volcano/pull/5843) + [release-1.15 backport(#5866)](https://github.com/volcano-sh/volcano/pull/5866)——Volcano deviceshare 路径下 HAMi Ascend 设备的常规抢占此前有缺陷,现已修。**对我们**:kubeos/npuserver 栈如果走 Volcano + HAMi NPU 共享路线,这个修复决定了"抢占能不能把 vNPU 份额抢回来";评估升级到含此修复的 1.15.x。
- [DRA: O(1) 容量扩缩(#5869 backport)](https://github.com/volcano-sh/volcano/pull/5869)——大容量 DRA 设备数场景防调度停滞,说明 Volcano 的 DRA 路径已有真实规模用户。
- [HyperNode 控制器支持独立部署(#5137)](https://github.com/volcano-sh/volcano/pull/5137) + [模块化 proposal(#5136)](https://github.com/volcano-sh/volcano/pull/5136)——网络拓扑感知(HyperNode)从 controller 单体里拆出来,是"拓扑感知作为独立能力输出"的架构信号。
- [queue-scoped overcommit 设计文档(#5746)](https://github.com/volcano-sh/volcano/pull/5746)——队列级超卖,配额精细化方向。

**Kthena**(v1.0.0 GA 后首个完整观察周,28 条合入,无新 release):

- 主线全是 **router / KV-cache-aware 路由的 GA 后收敛**:[kvcache 打分去中间 map(#1649)](https://github.com/volcano-sh/kthena/pull/1649)、[prefix-cache hash 预分配(#1628)](https://github.com/volcano-sh/kthena/pull/1628)、[tokenizer 端口校验(#1633)](https://github.com/volcano-sh/kthena/pull/1633)、[外部 provider 可观测与计量(#1370)](https://github.com/volcano-sh/kthena/pull/1370);另有多条 RBAC 缺权限修复([#1646](https://github.com/volcano-sh/kthena/pull/1646)、[#1623](https://github.com/volcano-sh/kthena/pull/1623))。
- 解读:功能面(KV-aware 路由、ModelServing 滚动升级)与 InferNex/KServe 赛道高度重合,但 RBAC 这类基础错误还在批量修,**1.0 的成熟度标签要打折**;当竞品/借鉴对象跟,暂不当依赖。
