# K8s AI 基础设施周报 2026-08-27

窗口:2026-08-20 → 2026-08-27

## 摘要(3 条以内)

1. **Kubernetes v1.37.0 正式 GA(08-26),`GenericWorkload`(WAS/gang)beta 随之落地**([release](https://github.com/kubernetes/kubernetes/releases/tag/v1.37.0))。更关键的是 WAS 主线本周把触角伸进核心工作负载控制器:新增 **KEP-6277(Workload API × StatefulSet)**([#6298](https://github.com/kubernetes/enhancements/pull/6298))和 **KEP-6276(Workload API × Deployment)**([#6295](https://github.com/kubernetes/enhancements/pull/6295),WIP)两个 alpha KEP——原生 gang 不再只服务 Job 类批作业,开始向 Deployment/StatefulSet 这类"常驻"负载渗透。这是"上游原生调度收编面持续扩大"的最强信号。
2. **NVIDIA GPU Operator v26.7.0 GA(08-21):DRA 从旁挂实验转正为 operator 一等公民**([release](https://github.com/NVIDIA/gpu-operator/releases/tag/v26.7.0)/[release notes](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/26.7/release-notes.html))。新 `GPUCluster` CR 直接托管 DRA driver,工作负载用 `ResourceClaim` 申领整卡/预置 MIG,并支持 KubeVirt 虚机经 DRA 直通 GPU(容器 + VM 同节点混跑)。上周"dra-driver 进 operator 正式镜像面"的判断本周兑现成产品能力。
3. **Kueue v0.19.2 / v0.18.6(08-20)出现向上游 scheduler-library 收敛的信号**:新增 `SchedulerLibraryIntegration` gate,把 TAS 节点就绪/`unschedulable` 判断**委托给上游 scheduler-library**([#14613](https://github.com/kubernetes-sigs/kueue/pull/14613)),而非自己在 TAS 缓存里判。叠加 JobSet 新 gang KEP"跟随 workload builder"([#1253](https://github.com/kubernetes-sigs/jobset/pull/1253))——生态项目本周集体从"绕开上游自建"转向"构建在上游 Workload API/scheduler-library 之上"。

## GPU / 加速器管理

- ⭐ **[gpu-operator v26.7.0](https://github.com/NVIDIA/gpu-operator/releases/tag/v26.7.0)(08-21,GA)**,把上期 pin 的组件(device-plugin v0.20.0、dra-driver v0.5.0、mig-manager v0.15.0、driver-manager v0.12.0、vgpu-device-manager v0.5.0、新驱动分支)一并转正。方向性要点:
  - **DRA 转正**:新 `GPUCluster` CR 管理 DRA driver,`ResourceClaim` 申领整卡与预置 MIG、按 attribute 选设备;门槛 K8s ≥1.34.2 / 驱动 ≥580 / CDI runtime。**对我们**:这是 device-plugin → DRA 的产品化模板,做加速器管理面要开始把 DRA/ResourceClaim 当"正在到来的默认申领语法"设计,而非可选后端。
  - **KubeVirt × DRA GPU 直通**:整卡直通给虚机,容器与 VM 工作负载同节点共存,HGX/NVL 上可选 Fabric Manager 分区做多卡 claim——虚机 + 容器统一 GPU 供给,是混合负载平台的关键拼图。
  - 驱动运维:`upgradePolicy` 支持逐资源升级配置、patch 升级时配置不变则原地重启驱动 pod、`kernelModuleType` 选开源/闭源内核模块;新增 `nvidia.com/gpu.deploy.client` 标签管理第三方 GPU 客户端 pod。
- gpu-operator 主线其余合入多为 CI/依赖/健壮性([#2792](https://github.com/NVIDIA/gpu-operator/pull/2792) 修无 GDS 配置时校验 panic、[#2782](https://github.com/NVIDIA/gpu-operator/pull/2782) 修驱动 DaemonSet 清理失败时的状态追踪、[#2779](https://github.com/NVIDIA/gpu-operator/pull/2779) 结构化 YAML 解析 kind 识别),无新方向。
- k8s-device-plugin、NFD 本周无 release、无实质合入。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

- ⭐ **Workload API 开始渗透核心控制器**:本周 enhancements 侧两个 alpha KEP 是主戏——
  - **[KEP-6277:Workload API × StatefulSet 集成(#6298)](https://github.com/kubernetes/enhancements/pull/6298)**,让 Workload + PodGroup 给有状态负载做 gang 调度;
  - **[KEP-6276:Workload API × Deployment 集成(#6295,WIP)](https://github.com/kubernetes/enhancements/pull/6295)**,给 Deployment 控制器接 Workload API。
  含义:v1.37 把 `GenericWorkload` 送进 beta 只是第一步,SIG 已在规划把"原生 gang / 成组语义"接进 Deployment/StatefulSet 这两个最常见的控制器。一旦落地,"要 gang 就得上 Volcano/Coscheduling"的前提会在常驻服务场景被进一步侵蚀。
- k/k sig/scheduling 本周合入 4 条,功能面仍是 v1.37 后的收尾:[#141253 为 PlacementFeasible 拒绝填充 UnschedulablePlugins](https://github.com/kubernetes/kubernetes/pull/141253)、[#141139 为 WAP(Workload-Aware Preemption)补齐对齐 pod preemption 的集成测试](https://github.com/kubernetes/kubernetes/pull/141139)——WAP(KEP-5710)的测试面在补齐,是它向 beta 推进的前置工。
- **常设研判(WAS 原生化 vs 生态调度器)**:本周基调是 **"收敛"压过"竞争"**。三条独立信号同指一个方向——上游把 Workload API 往 Deployment/StatefulSet 推(KEP-6276/6277)、Kueue 把 TAS 判断委托给上游 scheduler-library(#14613)、JobSet 新 gang KEP 明确"跟随 workload builder"(#1253)。**生态项目正主动把自己重构成"上游 Workload API 之上的策略层",而非平行栈**。研判更新:对 Volcano/Kueue/KAI,"厚层护城河(配额/公平/拓扑/设备共享)"仍在,但**"gang 原语归属"这块地已基本让给上游**;选型上,长期押注应偏向"能干净跑在原生 Workload API 上"的调度器。
