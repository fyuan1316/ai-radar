# K8s AI 基础设施周报 2026-11-26

> 窗口:2026-11-19 ~ 2026-11-26(v1.38 Code Freeze 后第一周,只有拿到 exception 的 PR 还在合入)。通用 K8s 能力(PodLevelResources GA、Pod 级 IPPR GA、watch cache 修复、v1.37.3/v1.36.7/v1.35.11 补丁)见同日 `k8s-core`,本期不重复。

## 摘要(3 条以内)

1. **KEP-5690 DRA 抢占拿到 exception 进了 v1.38 alpha**(k/k #143456,11-20 合入,gate `DRAPreemption` 默认关)。kube-scheduler 现在可以抢占「独占分配了节点本地设备」的低优先级 Pod,并为抢占者预留释放出来的设备。但 alpha **不覆盖 PodGroup Pod、独立 ResourceClaim、DRA 扩展资源和可消耗容量/共享设备**。换句话说,「gang + DRA」的抢占和「GPU 分片」的抢占,上游 1.38 都还做不到。
2. **Kueue v0.21.0 进入 rc(rc.0 11-19 → rc.2 11-24)**。DRA 两项升 beta 且默认开:按可消耗容量维度计配额、prioritized list(`firstAvailable`)。新增 alpha 的 LWS DisaggregatedSet 集成(按 slice 整体准入和抢占)。WAS 深度集成支持按 ClusterQueue 选 `KueueNative` 或 `KubeSchedulerDeepIntegration` 两种 planner。日志级别和 key 大面积调整,并有多条 ACTION REQUIRED。
3. **Volcano v1.16.1(11-26)** 把「只申请 DRA 资源的 Pod 绕过 gang」的修复带到了 1.16 线(上期只有 1.15.4/1.14.7),同时修了 subGroupPolicy 只写 `labelSelector` 时 PodGroup 永远调度不了的问题。gpu-operator main 合入 operator 多副本 HA,默认驱动升到 R620。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

冻结后 k/k 里 sig/scheduling 的 merged PR 共 13 个,**没有新的 WAS、gang、Workload 或 PodGroup 代码合入**。其余是 PodLevelResources/IPPR 等通用项(归 k8s-core),以及「同名 Pod 快速删除后重建导致调度器崩溃」修复(#141255)回合到 1.35~1.37。https://github.com/kubernetes/kubernetes/pull/144204

KEP 侧只做了冻结后的文档同步:KEP-5547 Job 集成(#6525,已合)、KEP-6089 控制器集成 API(#6521,已合)、KEP-5732 TAS(#6526,在审)、KEP-6276 Deployment 集成(#6528,在审,按 k/k #143235 的实际实现修订 scheduling 引用)。
- https://github.com/kubernetes/enhancements/pull/6525
- https://github.com/kubernetes/enhancements/pull/6526
- https://github.com/kubernetes/enhancements/pull/6528

本周 WAS 主线唯一的实质进展,是 DRA 抢占进了 1.38(详见下文 DRA 节)。

> **WAS vs 生态调度器研判:本周对 Kueue 是利好,对 Volcano/KAI 的 gang + 设备抢占地盘暂时没有挤压。**
> - **Kueue**:v0.21 让每个 ClusterQueue 自选 `KubeSchedulerDeepIntegration` planner(#19154),并支持在这种模式下做 TAS 抢占(#17681)、缓存虚拟 Pod 降低调度周期延迟(#18514)。Kueue 正在把「拓扑放置和抢占目标计算」交给 kube-scheduler 库,自己只做队列和配额。上游 WAS 越成熟,Kueue 越省力,两者是互补关系。
> - **Volcano / KAI**:KEP-5690 alpha 明确排除 PodGroup Pod 和共享/分片设备。也就是说,「整组 gang 的 GPU 抢占」和「vGPU/MIG 分片抢占」在上游 1.38 里还是空白。这正是 Volcano(gangpreempt/gangreclaim)和 KAI(consolidation)的核心地盘,**至少到 1.39 不会被原生能力覆盖**。Volcano 本周发版仍在修 DRA + gang 的基础正确性(见下文),说明它在 DRA 路径上的成熟度并不比上游领先。
> - **对我们产品的启示**:GPU 抢占的上游路径要分两段看。单 Pod 独占卡的抢占 1.38 起可以用 alpha 原生能力验证。gang 和分片的抢占在 1.39 之前仍需依赖 Volcano/HAMi 方案。产品文档和路线图不要承诺「原生 DRA 抢占覆盖 vGPU」。

### Kueue

- **v0.21.0-rc.0 / rc.1 / rc.2**(11-19 / 11-20 / 11-24),与 AI 集群相关的部分:https://github.com/kubernetes-sigs/kueue/releases/tag/v0.21.0-rc.2
  - **DRA 升 beta、默认开**:
    - 按 DeviceClass 的可消耗容量维度分别计配额(`KueueDRAIntegrationConsumableCapacity`,#17636)。请求被取整导致多扣配额时,Kueue 会报出来。
    - `firstAvailable` prioritized list(`KueueDRAIntegrationPrioritizedList`,#19158):每个备选都有 CEL selector 时,Kueue 会对照集群设备检查。
    - **ACTION REQUIRED**:如果关闭了 `KueueDRAIntegration`,必须同时关掉这两个 gate,否则 manager 起不来。
  - **DRA 新增 alpha**:`excludeDeviceClassNames`(#18632,上期已报)。DeviceClass 没在 `deviceClassMappings` 里时会发 Warning event(#16857)。MultiKueue 下,用 CEL selector 的 count 型映射可以在 manager 侧先预留配额,设备可用性改到 worker 上检查(#17916)。
  - **LWS DisaggregatedSet 集成(alpha,`DisaggregatedSetIntegration`)**(#17675):把一个 slice 里的所有角色当成一个 Workload 一起准入、一起抢占,保证 PD 分离推理「要么全起,要么都不起」。https://github.com/kubernetes-sigs/kueue/pull/17675
  - **LWS `groupIdentity: Hash` 被拒**(#18250,ACTION REQUIRED):这种模式下 leader Pod 会绕过准入直接运行。已经在 Kueue 管理下的 Hash 模式 LWS,需要删掉后用 `Ordinal` 重建。https://github.com/kubernetes-sigs/kueue/pull/18250
  - **Pod 组配额绕过修复**:Pod 可以把 `kueue.x-k8s.io/role-hash` 注解伪造成别的角色,拿着那个角色的配额预留跑超规格的 Pod。现在 Kueue 在移除 scheduling gate 前会校验 Pod 是否符合对应 PodSet(#13382)。**多租户场景下这是一个配额隔离问题**。https://github.com/kubernetes-sigs/kueue/pull/13382
  - **部分抢占(Partial Preemption)**(#14590、#18851、#19224):对开启了这项能力的弹性作业,回收配额时可以把 PodSet 缩到最小值,不必整体驱逐。已覆盖 Ray(RayCluster/RayJob/RayService,通过 `podset-partial-preemption-min-retained-count` 注解)和 Fair Sharing。这是训练和 Ray 集群「部分让出 GPU」的关键能力。https://github.com/kubernetes-sigs/kueue/pull/14590
  - **CapacityBuffer 准入检查(alpha)**(#17781):为 Workload 创建 autoscaler CapacityBuffer,等 Karpenter 等报告容量到位后再准入。https://github.com/kubernetes-sigs/kueue/pull/17781
  - `PriorityBoost` 从注解改为 `spec.priorityBoost` 字段,旧注解不再生效(#19177)。RayCluster 的 PodsReady 改为看 head 是否就绪(默认开,需要 KubeRay≥1.3)。RayService 改用顶层 `spec.suspend`(需要 KubeRay≥1.7)。
  - **运维注意**:几十处日志从 V2 降到 V3,并重命名了 key(#17746/#17747/#19034 等)。依赖 Kueue 日志做告警或看板的,升级前必须复核。
- **v0.20.7 / v0.19.14**(11-19),只有 bug 修复,DRA 相关三条:
  - DeviceClass 或 LimitRange 变化导致配额重算时,Workload 带着旧的扣费重新入队(#18781)。
  - 同一 driver/name 的两个 counter 源会重复扣配额,现在配置校验会拒绝(#18923)。
  - ResourceClaimTemplate 引用了不存在的 DeviceClass 时,Workload 仍被准入并占着配额(#18936)。
  - 此外,TAS 在弹性作业缩容后没有释放拓扑容量的问题已修(#18928)。
  - https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.7

### DRA

- **KEP-5690 DRA 抢占 alpha 合入**(k/k #143456,+6959 行,11-20):
  - gate 为 `DRAPreemption`,默认关。
  - 覆盖范围:Pod 自有的 ResourceClaim(比如从 ResourceClaimTemplate 生成的)里独占分配的节点本地设备。调度器模拟驱逐低优先级 Pod,把释放出来的设备「持有」给抢占者,直到它调度成功。
  - 不在 alpha 范围:独立 claim、PodGroup Pod、DRA 扩展资源、可消耗容量和共享设备。
  - 基准测试:500 节点下抢占吞吐约 20.6 pods/s,可分区设备约 49.9 pods/s。
  - 这个 KEP 在 11-19 一度被移出 v1.38 milestone,拿到 exception 后在 11-21 恢复。https://github.com/kubernetes/kubernetes/pull/143456 、https://github.com/kubernetes/enhancements/issues/5690
- **KEP-6080 DRA Derived Attributes**:1.37 已经 alpha,本周开始逐条核对 beta 准入条件,跟踪 issue 是 k/k #144456。它允许 DeviceRequest 用 scoped CEL 表达跨厂商的设备共同分配(比如 GPU 和 NIC 同拓扑)。https://github.com/kubernetes/enhancements/issues/6080
- **KEP-6352 DRA Node Allocatable Capacity Reservation**(从 KEP-5517 拆出来的,未定版本):解决的是驱动在设备分配时拉起的守护进程(**比如 GPU MPS control daemon**)占用的资源不属于任何 Pod、无法记账的问题。和 HAMi 新的 mps-v3 模式,以及 device-plugin MPS 的资源记账直接相关。https://github.com/kubernetes/enhancements/issues/6352
- 其他本周有讨论的 DRA KEP(均未定版本):KEP-5719 Reserved Capacity(预留备用加速器,用于故障替换)、KEP-5691 restricted sharing(驱动限制设备共享方式)、KEP-5234 ResourceSlice Mixins、KEP-6006 Health-Aware Topology(把设备健康当作拓扑维度)。
  - https://github.com/kubernetes/enhancements/issues/5719
  - https://github.com/kubernetes/enhancements/issues/6006
- `kubernetes-sigs/dra-evolution` 仓库仍然 404(第二期确认)。
