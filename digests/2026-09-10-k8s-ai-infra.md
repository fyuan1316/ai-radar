# K8s AI 基础设施周报 2026-09-10

窗口:2026-09-03 ~ 2026-09-10。数据源:各仓 releases + 窗口内 merged PR;kubernetes/kubernetes 加扫 `sig/scheduling` label merged PR;kubernetes/enhancements 扫 AI 相关 KEP。

## 摘要(3 条以内)

1. **上游原生调度进入 v1.37 "WAS beta 冲刺"**:gang(KEP-4671)、workload-aware preemption(KEP-5710)、topology-aware workload scheduling(KEP-5732)、DRA ResourceClaim-for-Workloads(KEP-5729)四个 KEP 全部标 **beta @ v1.37**;同时新增三个 alpha KEP——WAS Controller APIs(KEP-6089)、CompositePodGroup API(KEP-6012)、Decouple PodGroup API(KEP-5832)。本窗口 k/k 的 sig/scheduling merged PR 大半在落地这条线(GenericPodGroup 挪进 staging、CompositePodGroup 进队列指标)。这是判断"生态调度器长期被挤压到什么位置"的最强信号。
2. **DRA Prioritized List(KEP-4816)GA 并锁 default-on @ v1.37**(enhancements #6085)。DRA 的"按优先级列表选设备"能力转正,配合 ResourceClaim-for-Workloads 进 beta,device-plugin 替代路线又实。
3. **Kueue 主动往上游 WAS 库靠**:v0.19.3 新增 `SchedulerLibraryIntegration` feature gate,开启后给 Kueue 托管 job 的 Pod 也打 `kueue.x-k8s.io/workload` 注解(此前只有 TAS 路径打)——Kueue 把自己接进上游 scheduler library 的路径已经在跑。反观 Volcano 本窗口只有 bugfix,主仓无演进。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

v1.37 是 WAS 主线的关键版本。本窗口 KEP 状态与 k/k 落地 PR 拼出的全貌:

| KEP | 能力 | 目标 stage @ 版本 |
|---|---|---|
| KEP-4671 Gang Scheduling | 原生成组调度 | **beta @ v1.37** |
| KEP-5710 Workload-aware preemption | 按 workload 整体抢占 | **beta @ v1.37** |
| KEP-5732 Topology-aware workload scheduling(TAS) | 拓扑感知成组放置 | **beta @ v1.37** |
| KEP-5729 DRA ResourceClaim Support for Workloads | workload 级 ResourceClaim | **beta @ v1.37** |
| KEP-6089 WAS Controller APIs | WAS 控制器 API 面 | alpha @ v1.37(新) |
| KEP-6012 CompositePodGroup API | 组合式 PodGroup(嵌套成组) | alpha @ v1.37(新) |
| KEP-5832 Decouple PodGroup API | 把 PodGroup API 从内核解耦 | alpha @ v1.36 |

本窗口 k/k `sig/scheduling` merged PR(共 20 条,挑 WAS 相关):
- **#141910 Move GenericPodGroup to staging** —— 把 GenericPodGroup 类型挪进 staging,对应"两个 feature gate 合并为 GenericWorkload / 公开 API"的动作。https://github.com/kubernetes/kubernetes/pull/141910
- **#141800 scheduler: support CompositePodGroup in queue metrics** —— 队列指标新增 `compositepodgroup` 实体类型,CPG 与 PG / Pod 并列进 `scheduler_queued_entities`;关联 KEP-6012。https://github.com/kubernetes/kubernetes/pull/141800
- **#141864 Differentiate between PG and CPG correctly inside findNodeAndParent** —— 调度树里正确区分 PodGroup 与 CompositePodGroup 的父子定位。https://github.com/kubernetes/kubernetes/pull/141864
- #141576 优化 `isEntityWorthRequeuing`(无 pending 插件的 pod group 重排队路径);#141557 builder 库实现 `generateWorkloadName` / `generatePodGroupName`;#139472 scheduler 在 TAS 放置选择时尊重 `NominatedNodeName`。

**研判(WAS 原生化 vs 生态调度器)**:这次 v1.37 是上游把 gang + preemption + topology + DRA 四件套一次性推 beta,并同步铺 CompositePodGroup / WAS Controller API 两个新 alpha —— 上游正在把"成组调度 + 拓扑 + 抢占 + DRA claim"做成内核原生的一等公民,直接对标 Volcano/KAI 的核心卖点。
  - 对 **Volcano**:gang 独占性被进一步稀释,尤其 CompositePodGroup 补上"嵌套/组合成组"这个 Volcano 靠 PodGroup+子任务实现的场景;Volcano 本窗口主仓无功能演进,只有 agent-scheduler 跳过 not-ready 节点的 bugfix(#5927),节奏上被动。
  - 对 **Kueue**:利好。Kueue 已明确把自己接进 upstream scheduler library(见下),WAS beta 化等于给 Kueue 免费升级底座,Kueue 守住"配额/队列/公平"这层。
  - 对我们:**v1.37 应作为"原生调度栈是否够用"的重新评估节点**。若 gang+TAS+preemption beta 稳定,自研/集成生态调度器的必要性主要落在"配额与多租户策略"(Kueue 域)和"厂商加速器亲和"(Volcano/HAMi/昇腾域),纯 gang 场景可考虑直接压到上游。
