## 调度(kube-scheduler)

- **IPPR 调度抢占升 beta、默认开(v1.38)**:一个 Pod 的原地扩容如果处于 `Deferred`(节点暂时放不下),scheduler 现在会抢占低优先级 Pod 给它腾资源。和 alpha 相比有两处**会影响自定义调度器**:
  - 自定义插件默认不参与 deferred resize 评估,要参与需实现 `RelevancePlugin`(`IsRelevantForPodResize`)接口;
  - 覆盖了默认 `Bind` 插件的自定义 profile,必须在 Bind 阶段启用 `DeferredPodScheduling`。
  - 我们如果有自研调度插件或二次封装的 scheduler profile,升 1.38 时要逐项核对这两点。https://github.com/kubernetes/kubernetes/pull/143158
- **调度框架新增 first-fit 节点过滤选项 `WithFirstFit`**:框架层新增的选项,release note 为 NONE,不面向终端用户;大集群下可以少做全量 Filter,值得在我们的调度扩展里评估。https://github.com/kubernetes/kubernetes/pull/143976
- **KEP-5869 通配符 Toleration Key**(provisional,仍在讨论):允许 toleration 的 key 用通配符,对多类加速卡污点的统一放行有用,目前还没进 milestone。https://github.com/kubernetes/enhancements/pull/5880
- 边界提示(归 `k8s-ai-infra`,这里不展开):KEP-5710 Workload-aware preemption **推迟 GA**,feature gate 并入 GenericWorkload(https://github.com/kubernetes/enhancements/pull/6491);KEP-4671 继续停在 beta(https://github.com/kubernetes/enhancements/pull/6494);KEP-5547 Job Scheduling 升 beta(https://github.com/kubernetes/kubernetes/pull/143188)。

## 节点 & kubelet

都是 v1.38 code freeze 前合入的,按阶段分组:

- **默认开 / beta**
  - **DefaultPodSysctls 默认开**(KEP-5996)。https://github.com/kubernetes/kubernetes/pull/143575
  - **h2c 探针 beta 默认开**:HTTP 探针可以用 `protocol: HTTP2` 走 h2c,对 gRPC/HTTP2 推理服务的健康检查直接有用(KEP-5999)。https://github.com/kubernetes/kubernetes/pull/143899
  - gRPC 探针 TLS 升 beta(KEP-4939)。https://github.com/kubernetes/kubernetes/pull/143889
  - **CRIListStreaming beta 默认开**:kubelet 对 CRI 的 List 调用改为流式(beta 默认开)。https://github.com/kubernetes/kubernetes/pull/144062
- **alpha / 新能力**
  - **Network Isolated Pods(KEP-6313)**:新增 `spec.podNetwork: Isolated`,Pod 只有 loopback、没有 Pod IP、不能用 hostPort 和网络探针,只会调度到 CRI 声明支持 `pod_network_isolated` 的节点。KEP 文档已同步到最终 API。适合跑离线批处理或不受信代码沙箱(例如 Agent 代码执行)。https://github.com/kubernetes/kubernetes/pull/143280 / https://github.com/kubernetes/enhancements/pull/6517
  - **DynamicContainers**:新增 `pods/dynamic` 子资源,可以向**运行中的 Pod 增删普通容器**,kubelet 侧已实现。默认的 admin/edit/view 角色**不包含**这个子资源的权限,需要显式授权,做多租户 RBAC 时要注意。https://github.com/kubernetes/kubernetes/pull/143715 / https://github.com/kubernetes/kubernetes/pull/143714
  - **Topology Manager `numa-allocation-strategy`**(alpha options):NUMA 亲和打分相同时,可以按 `most-allocated`(打包)或 `least-allocated`(打散)选择。对 GPU/NIC 的 NUMA 对齐策略是一个新旋钮。https://github.com/kubernetes/kubernetes/pull/142226 ;配套新增 NUMA 选择指标。https://github.com/kubernetes/kubernetes/pull/142529
  - **`--system-reserved` / `--kube-reserved` 支持 hugepages**:可以给宿主服务(例如 DPDK、RDMA 组件)预留大页,预留量从 allocatable 中扣除。https://github.com/kubernetes/kubernetes/pull/142837
  - **OCI seccomp profile**:kubelet 通过 runtime 拉取 OCI 制品形式的 seccomp profile,不再用的会被 GC(SecurityProfileOCI alpha,KEP-6061)。https://github.com/kubernetes/kubernetes/pull/142515
  - **InPlaceNodeResourceResize**:超出节点总 allocatable 的 resize 现在标为 `Infeasible`(之前是 `Deferred`),节点扩容后自动重试(KEP-3953)。https://github.com/kubernetes/kubernetes/pull/143174
  - KEP-5474 非特权容器可写 cgroup(alpha):KEP 已对齐实现,`Writable` 改名为 `ReadWrite`。https://github.com/kubernetes/enhancements/pull/6519
  - KEP-5359 Workload Controlled Swap(alpha):swap limit 写进 Pod status,beta 前需要先定下节点级 swap 总量的约束。https://github.com/kubernetes/enhancements/pull/6513 ;Pod-level resources 支持 swap。https://github.com/kubernetes/kubernetes/pull/143760
  - CRI v1 新增容器 ulimits 字段与能力位(KEP-5758,11-19 合入)。https://github.com/kubernetes/kubernetes/pull/137023
  - `kubectl drain` / `uncordon` 会写入 `DrainInProgress` / `Drained` 节点 Condition,运维平台可以直接读取 drain 状态。https://github.com/kubernetes/kubernetes/pull/143313
- **新 KEP(provisional)**
  - **驱逐时按 surge 补容量,不再被 PDB 卡死**:单副本 + `minAvailable: 1` 的工作负载可以先起替身、再完成驱逐,与 KEP-4212 声明式节点维护配合。https://github.com/kubernetes/enhancements/pull/6245

## 自动扩缩容(VPA / CA / Karpenter)

- **VPA**:
  - 发布 chart **0.17.0**(appVersion 仍为 VPA 1.8.1,无新二进制),只新增了可配置的 liveness/readiness/startup 探针。https://github.com/kubernetes/autoscaler/releases/tag/vertical-pod-autoscaler-chart-0.17.0 / https://github.com/kubernetes/autoscaler/pull/10687
  - **KEP-1287 主线的关键进展在 k/k**:IPPR 调度抢占在 v1.38 默认开(见"调度"),VPA in-place 模式碰到节点放不下时,终于能靠抢占落地,不再长期卡在 Deferred。
  - **新 KEP-6508 Pod Resource Hints for Autoscalers**(sig-autoscaling/node,11-12 新建,provisional):给 Pod 加 `status.resourceHints.replacement`,通过新的 `pods/resourcehints` 子资源写入,由 VPA 这类 Pod 级扩缩器发布"替身 Pod 实际会按多少 request 准入"。CA/Karpenter 规划整合时直接读这个值,不再错误假设替身和原 Pod 一样大,从根上解决 VPA 原地缩容后节点合并来回抖动的问题。kube-apiserver、VPA、Karpenter 都已有原型。https://github.com/kubernetes/enhancements/pull/6509
  - **KEP-6438 Resize Gates for In-Place Pod Resize**(provisional,本周有更新):让树外配额控制器(例如 Kueue 一类)先拦住 IPPR 的扩容请求,自己准入后再放行。https://github.com/kubernetes/enhancements/pull/6459
- **Cluster Autoscaler**:无 release,只有 provider 级修复:AWS 把 Terminating:Retained 视为终止中(https://github.com/kubernetes/autoscaler/pull/10679)、Azure 把不存在的 VMSS 按 size=0 规划(https://github.com/kubernetes/autoscaler/pull/10680)、CoreWeave 修了 DecreaseTargetSize 会误删已有节点的问题(https://github.com/kubernetes/autoscaler/pull/10628)。
- **Karpenter**:无 release,main 上有三条值得注意:
  - **NodePool 级 drift 指数退避**:某个 NodePool 替换持续失败时,按 1m→2m→4m→8m(上限 10m)退避,不再让其他 NodePool 一直等不到处理。https://github.com/kubernetes-sigs/karpenter/pull/3178
  - **破坏性变更 `Offering.Incompatible` → `Offering.Compatible`**:只影响 cloud provider 实现方,自研 provider 要跟着改。https://github.com/kubernetes-sigs/karpenter/pull/3617
  - **DRA 开启但集群不提供 `resource.k8s.io/v1`(1.31–1.33)时,启动阶段直接报错退出**,之前会 panic 并 crashloop。https://github.com/kubernetes-sigs/karpenter/pull/3635
- **Cluster API v1.15.0-beta.1**(11-17,pre-release):ClusterTopology 升 beta 默认开;MachineTaintPropagation 升 beta 默认开;PriorityQueue/ReconcilerRateLimiting GA;原地更新扩展可以声明"不影响可用性"(这时不再多起一台 VM),单控制面集群也支持原地更新;MHC 支持 CEL 健康规则;DynamicCache 让 1K 集群 / 27K 机器规模下内存降 37–50%。https://github.com/kubernetes-sigs/cluster-api/releases/tag/v1.15.0-beta.1

## 策略 & 安全

- **Kyverno v1.20.0**(11-12),**大版本,破坏性**:
  - **旧引擎被删**:legacy `kyverno.io/v1` ClusterPolicy/Policy 的执行路径已从 admission、background、reports 三个控制器中移除,引擎本身和 Go API 也删了(https://github.com/kyverno/kyverno/pull/18265)。webhook 硬拒旧策略的新建和改 spec(https://github.com/kyverno/kyverno/pull/17535)。
  - **迁移保护**:Helm 安装/升级时有默认开启的检查,集群里残留旧策略会被拦下;旧 CRD 带 `resource-policy: keep`,不会被 prune;启动时会通过指标报告残留的旧策略。

  - **安全修复**:apiCall.service 出口黑名单加固(含 IPv6 内嵌 IPv4 绕过);CEL 求值加成本上限;修复多项依赖 CVE。
