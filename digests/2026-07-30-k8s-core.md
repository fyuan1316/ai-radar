## K8s 核心版本节奏

- **1.37 = beta / 特性冻结阶段**。v1.37.0-beta.0 于 2026-07-20 打 tag(窗口前 3 天),本窗口内 `kubernetes/kubernetes` **无新 tag**。含义:1.37 的 feature gate 集合已基本锁定,本周 enhancements 仓的 KEP PR 绝大多数是"让文档追上已合入实现"或冻结前的状态回退,而非新特性入场。GA 预计按惯例在 8 月底前后。
- **补丁线**:最新补丁 v1.36.3(07-22,窗口前一天),窗口内无新 patch tag。维护分支 1.35/1.36 保持常规节奏。
- **本周唯一实质状态变更**:KEP-6132(PreQueueingHint 调度事件处理扩展点)**beta → alpha 回退**,1.37 内默认关闭、opt-in,beta 重定于 1.38。这是"赶不上冻结质量门槛就降级保发版"的典型操作,不影响现网。 https://github.com/kubernetes/enhancements/pull/6261

## 调度(kube-scheduler)

- **PreQueueingHint 扩展点(KEP-6132)回退 alpha**(见上)。该扩展点用于更精细地控制调度事件如何把 Pod 从 unschedulable 队列拉回 active 队列,对大规模集群的调度吞吐有影响;1.37 内仍不建议生产开启。 https://github.com/kubernetes/enhancements/pull/6261
- **PodGroupPreemptionPolicy(KEP-5710)补文档 + 独立 feature gate**:实现里遗漏了该字段,导致它比 GenericWorkload 主 gate 慢一个 release 周期,故拆出单独 gate 以免拖慢主特性晋级。这条属核心调度器的 **Pod 组级抢占策略**,与 AI 侧 gang scheduling 相邻(gang 归 k8s-ai-infra),但因为它落在 in-tree scheduler 的通用抢占语义上,这里记一笔:未来做批任务/组调度时,抢占策略将有原生字段可用。 https://github.com/kubernetes/enhancements/pull/6222

## 节点 & kubelet

- **Dynamic Containers(KEP-5972,新)**:sig-node 提出"让容器可变(mutable containers)",即在不重建 Pod 的前提下动态调整容器。仍在 API review 阶段、未定 alpha 目标版本,但方向上与 in-place resize 同属"降低 Pod 重建成本"的大线,值得长期跟。 https://github.com/kubernetes/enhancements/pull/6169
- **CRI cgroup mount mode(KEP-5474)**:修订 CRI API 以支持 cgroup 挂载模式,**alpha 从 1.37 顺延到 1.38**。属冻结前的目标版本调整。 https://github.com/kubernetes/enhancements/pull/6260
- **最小 per-pod PID 限制 1024 → 128(KEP-6063)**:基于 OpenShift 集群实测 PID 用量,把 `spec.resources.limits.pid` 允许的最小值从 1024 下调到 128,让密集小容器场景能设更紧的 PID 上限。已合文档。 https://github.com/kubernetes/enhancements/pull/6217
- **lifecycle hook 的 ExecAction 超时(KEP-4929,新)**:给 postStart/preStop 的 exec hook 加超时,避免卡死 hook 拖住 Pod 生命周期。开放中。 https://github.com/kubernetes/enhancements/pull/6235
- **KubeletInUserNamespace(KEP-2033)** 清理无用 label,收尾性改动。 https://github.com/kubernetes/enhancements/pull/6256

## 自动扩缩容(VPA / CA / Karpenter)

- **VPA 默认版本升至 1.7.1**(autoscaler #10057),并修复 **VPA checkpoint 加载顺序**(#10045)——保证从 checkpoint 恢复历史推荐值时顺序正确,直接影响重启后推荐质量。 https://github.com/kubernetes/autoscaler/pull/10057 · https://github.com/kubernetes/autoscaler/pull/10045
  - VPA 的关键线仍是 **in-place pod resize(KEP-1287)** GA 后 VPA 才在生产真正可用;本周该线无新进展,继续观望 1.37/1.38。
- **Cluster Autoscaler:不可调度 Pod 的优雅降级机制**(#9242):当 Pod 长期不可调度时引入 graceful degradation,避免 CA 反复无效扩容/日志噪声。对"扩不出来的 GPU/大规格节点"场景直接相关。 https://github.com/kubernetes/autoscaler/pull/9242
- **Karpenter**:新增 `karpenter_pods_disrupted_total` 计数器(#3015),把"因中断/整合被驱逐的 Pod 数"做成可观测指标,利于评估整合策略激进度。 https://github.com/kubernetes-sigs/karpenter/pull/3015

## 网络 & 存储(大盘)

### Cilium v1.20.0(07-29,重点)
主版本发布,2660+ commits。升级前注意:legacy Mutual Auth、Envoy Go 扩展、Kafka-aware policy、`cilium.io/v2alpha1` CiliumNodeConfig、libnetwork 集成、自定义 CNI 配置的用户需按 upgrade notes 操作。 https://github.com/cilium/cilium/releases/tag/v1.20.0

- **Gateway API v1.4 → v1.6.1**:一次跨两个上游版本。新增 **ListenerSets**(平台团队持有 Gateway、应用团队自管 listener 的委派模型)、**BackendTLSPolicy**(网关到后端的 TLS)、**TCPRoute/UDPRoute**(非 HTTP 服务纳入同一 Gateway 模型)、**ExternalAuth**(GEP-1494,请求到达应用前经外部服务鉴权)、HTTPRoute 原生 CORS。
- **可扩展数据面(Extensible Datapath)**:云厂商可用独立版本化的 eBPF 程序扩展/插桩 Cilium 数据面,不必维护 fork。
- **自动 netkit 选择**:`bpf.datapathMode=auto` 在支持的内核用 netkit、否则回落 veth(默认仍 veth)。
- **IPAM**:AWS ENI IPAM 的 **IPv6 前缀分配(Beta)**;支持从 cluster-pool 平滑迁移到 multi-pool IPAM,无需重建集群。
- **服务与 ClusterMesh**:LB 支持 K8s **PreferSameZone / PreferSameNode** 拓扑流量分发;Maglev 支持按 EndpointSlice 权重(weight=0 优雅排空);**MCS API 转 stable**。
- **策略**:支持上游集群级 **ClusterNetworkPolicy(KCNP)**,含 Admin/Baseline 分层;IPv6 策略拒绝可回 ICMPv6 不可达。
- **加密**:ztunnel 身份管理增强(内部 CA 或 SPIRE 工作负载身份 + 新增 Prometheus 指标)。
