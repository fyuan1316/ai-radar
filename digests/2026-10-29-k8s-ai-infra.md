# K8s AI 基础设施周报 2026-10-29

> 窗口:2026-10-22 ~ 2026-10-29。通用 K8s 能力见同日 `k8s-core`;昇腾/NV/HAMi 下游调度栈见各 watch task。

## 摘要(3 条以内)

1. **WAS 主线实质推进:CompositePodGroup API 升 beta(`scheduling.k8s.io/v1beta1`,v1.38,KEP-6012)**。原生"层级化成组调度"从 v1.37 alpha 一个版本就冲到 beta,配套 10+ 支撑 PR 同期落地(统一 PodGroup/CompositePodGroup 处理、抢占策略解析、victim 排序统一)。这是上游把 gang/Workload 能力收编进 kube-scheduler 的最硬信号,直接挤压 Volcano gang 的独占地盘。
2. **Kueue v0.20.3 / v0.19.10**:MultiKueue 支持 RayService 在 worker 集群内的 in-tree autoscaling(弹性 workload slice);修 DRA DeviceClass 隐式扩展资源名的配额归账 bug——Kueue 继续把 DRA/Workload 路径当默认追。
3. **DRA(重中之重)多点动作**:consumable capacity(可共享容量)API 校验收紧进 v1.38、DeviceToleration 支持 NoExecute 空 effect 驱逐、allocator 性能优化——分片/共享语义与设备污点驱逐都在补齐 production 细节。

## 调度 & 资源分配

### 上游原生调度(WAS / gang / Workload API)

**头条:CompositePodGroup API 升 beta。** PR #143088(10-28 合入,milestone v1.38,KEP-6012)把 CompositePodGroup 从 v1.37 alpha 直接推到 `scheduling.k8s.io/v1beta1`。CompositePodGroup 解决"层级化调度需求"——即一个 workload 由多组角色(如 PD 分离的 prefill/decode、LWS 的 leader/worker)构成、需要成组且可嵌套成组地原子调度,正是上游对标 Volcano PodGroup / LWS gang 的原生答案。
- KEP-6012:https://github.com/kubernetes/enhancements/issues/6012
- 升 beta PR:https://github.com/kubernetes/kubernetes/pull/143088

同期支撑 PR(均 v1.38),显示这条线在从"能跑"走向"生产可用":
- #143354 统一 queue/plugins 里 PodGroup 与 CompositePodGroup 的处理路径 https://github.com/kubernetes/kubernetes/pull/143354
- #143253 修复从 PriorityClass 解析 PodGroup 抢占策略 https://github.com/kubernetes/kubernetes/pull/143253
- #142955 抢占的 disruption 指标按 victim 类型参数化,统一"独立 Pod"与"workload Pod"的受害者排序 https://github.com/kubernetes/kubernetes/pull/142955
- #142143 验证抢占期间置 NNN(NominatedNodeName)、绑定后清除(PodGroup 抢占语义) https://github.com/kubernetes/kubernetes/pull/142143

**新 KEP(苗头):KEP-6413 PodGroup 运行时满足度条件(runtime satisfaction condition)。** PR #6414(provisional,目标 alpha v1.39)提出给 `PodGroupStatus.Conditions` 加一个运行时是否"成组满足"的 condition,**无 schema 变更、纯 kube-scheduler feature gate**。recovery policy 被拆成 future work 不阻塞。这是 gang 可观测性/上层控制器对接的关键钩子,值得盯。https://github.com/kubernetes/enhancements/pull/6414

> **WAS vs 生态调度器研判:这周是明确挤压。** CompositePodGroup 一个版本从 alpha 到 beta、抢占 victim 排序把"workload Pod"与普通 Pod 统一进原生框架,意味着上游把"成组 + 成组抢占"两件 Volcano 的核心价值同时原生化。对我们产品的启示:(1) gang scheduling 作为"选 Volcano 的理由"的权重在快速衰减,中期要把产品叙事从"我们带 gang"转向"我们带 gang 之上的配额/公平/多租(Kueue 层)";(2) 反而利好 Kueue——Kueue 已把 Workload/DRA 当默认路径,CompositePodGroup beta 后 Kueue 可直接复用原生成组,不必自带调度器;(3) 需要开始评估"CompositePodGroup beta 版本(v1.38)落地后,我们的昇腾/vGPU 调度栈如何对接原生 PodGroup 而非仅 Volcano PodGroup"。

### Kueue

**v0.20.3 / v0.19.10(均 10-22)**,两条线同步发补丁:
- Feature:MultiKueue 支持 worker 集群上 RayService 的 in-tree autoscaling,用弹性 workload slice 实现(需 `MultiKueueRayInTreeAutoscaling` gate)——多集群推理/训练的弹性能力补齐。(#17466)
- Feature:classical preemption 性能优化,复用候选排序 + 按需生成候选,`ClassicalPreemptionCandidateOrderCache` alpha gate(默认关)。(#17296/#17295)
- Bug(DRA):修复请求 DeviceClass 隐式扩展资源名 `deviceclass.resource.kubernetes.io/<class>` 时被当普通扩展资源、配额不计入 `deviceClassMappings` 逻辑资源导致 workload 卡 pending。(#17434)——DRA 配额归账是生产部署的现实坑。
- Bug:Deployment/StatefulSet/LWS 在存在名为 `default` 的 WorkloadPriorityClass 时误拒更新的问题修复。(#17309/#17313)
- https://github.com/kubernetes-sigs/kueue/releases/tag/v0.20.3
