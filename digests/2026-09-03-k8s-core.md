## 节点 & kubelet

节点侧是本周信号最密的地方,均为 **1.38 方向的新/推进 KEP**(实现多数尚未落地):

- **Hermetic(网络隔离)Pod(KEP-6313,新,sig-node + sig-network)** —— 给 Pod 加 `spec.networkMode`(`Cluster` / `Host` / `None`),`None` 时 Pod 退出集群网络、只保留 loopback。对"完全离线的批处理 / 不需要 Service 网络的敏感负载 / 强隔离多租户"是原生抓手,安全边界比 NetworkPolicy 更硬。9/2 新提。https://github.com/kubernetes/enhancements/pull/6317
- **KEP-6303 in-place 容器 resize 上 Windows(provisional,sig-node)** —— KEP-1287 在 Linux 已 stable,但 Windows kubelet 仍拒绝所有 resize;本 KEP 补齐平权。**in-place resize 线的关键一步**(见下)。8/31 新提。https://github.com/kubernetes/enhancements/pull/6304
- **KEP-6122 可配置扩缩延迟 + Pod 资源暴露(target alpha v1.38,sig-node)** —— 让容器可读到自身被分配的资源、并配置扩缩延迟,和 in-place resize / VPA 反馈闭环相关。https://github.com/kubernetes/enhancements/pull/6314
- **KEP-5683 kubectl drain 写节点 conditions(sig-node)** —— drain 时把节点生命周期状态(如正在排空)写成 Node condition,给上层 controller/运维更清晰的上下文(锁/并发写者留待后续 KEP)。对我们做节点运维编排有用。8/31 新提。https://github.com/kubernetes/enhancements/pull/6309
- **KEP-6030 内存型卷(memory-backed volumes)动态 resize → beta 更新(sig-node + sig-storage)** —— emptyDir(medium=Memory)等内存卷支持在线扩缩,推进到 beta。https://github.com/kubernetes/enhancements/pull/6320
- 承上周仍在推进:KEP-5972 Dynamic Containers、KEP-6252 Hugepages Reservation、KEP-4205 PSI(本窗口无新增量)。
