# K8s 自身核心周报 2026-10-29

窗口:2026-10-22 → 2026-10-29

## 摘要(3 条以内)

1. **Go 工具链 CVE 带外补丁扫过半个生态**:Cilium 在 10-23 对 1.18/1.19/1.20 三条 stable 线同日带外发补丁,根因是 **CVE-2026-111943**(golang/go#82345)——被攻陷的 eMudhra 中间 CA 证书仍被信任,修复方式是升 Go 到 1.26.10 重建。这不是 Cilium 独有问题:凡自研/集成的 Go 组件(含我们自家镜像)都应同步升 Go 1.26.10 并重建。https://github.com/cilium/cilium/releases/tag/v1.20.4
2. **K8s 月度 patch 批次 + v1.38 第三个 alpha**:10-28 四条 stable 线齐发 patch(v1.37.2 / v1.36.6 / v1.35.10 / v1.34.13),同日出 v1.38.0-alpha.3。无新 minor 的 rc.0 / GA,**deep-dive 本周不触发**,v1.38 仍在 alpha 早期。https://github.com/kubernetes/kubernetes/releases/tag/v1.37.2
3. **自动扩缩容信号集中在 Karpenter**:v1.15.0 引入的回归——偏好 `capacity-type: reserved` 的 Pod 在预留池满后永久卡 Pending——已在 **v1.15.1** 修复(用预留实例跑 AI 训练/推理的要升级);同时修了 SIGTERM 优雅关闭(影响滚动升级中断时长),并为 **Karpenter × VPA prediction** 节点 right-sizing 补了 E2E,这条整合值得跟。https://github.com/kubernetes-sigs/karpenter/releases/tag/v1.15.1

通用调度器方向本周**无 release、无实质通用改动**。唯一相关 KEP 偏 gang/PodGroup 语义(归 `k8s-ai-infra` 边界,仅作提示):

## 节点 & kubelet

无 release;两条 sig/node 的新/推进 KEP 与我们的运维/调度面相关:

- **KEP-6472 kubectl describe node 展示 Pod extended resource 请求**(sig/node,本周 10-21 新建 provisional):让 `kubectl describe node` 直接显示 Pod 的 extended resource(如自定义加速卡资源)请求/限制,补齐当前只显示节点总量、需手工推算的空白。对排查"卡/资源分到哪了"有直接运维价值。https://github.com/kubernetes/enhancements/pull/6473
- **KEP-6262 节点维护期允许 Job pod 被替换**(sig/node,9-21 建、本周 10-26 更新):节点 drain/维护期间允许 Job 的 pod 被替换/重建,改善维护窗口下的作业连续性。https://github.com/kubernetes/enhancements/pull/6402

## 自动扩缩容(VPA / CA / Karpenter)

- **VPA / Cluster Autoscaler**:`kubernetes/autoscaler` 窗口内**无 release**。最近一批(VPA 1.8.1 / 1.7.3 / chart 0.15.0)发布于 2026-10-21,刚好落在窗口前一天(上期已覆盖:修 InPlace 模式把数天前 lastState OOM 误判为"刚发生"的 bug,KEP-1287 in-place resize 线稳定性相关)。
- **Karpenter 两个 patch(10-23)**:
  - **v1.15.1**:含一处**重要回归修复**(#3456 修 #3451)——v1.15.0 引入的回归让偏好 `capacity-type: reserved` 的 Pod 在预留池满后**永久卡 Pending**;另有 NodeRepair enqueue 修复、Go 1.26.10。https://github.com/kubernetes-sigs/karpenter/releases/tag/v1.15.1
  - **v1.14.3**:纯 Go 1.26.10 + x/net bump,无功能变更。https://github.com/kubernetes-sigs/karpenter/releases/tag/v1.14.3
- **Karpenter 窗口内值得关注的 merged PR**:
  - **恢复 SIGTERM 优雅关闭**(#3490):此前 `context.Background()` 换掉 knative signal context,导致 SIGTERM 直接杀进程、leader lease 不释放,每次优雅重启都要干等整个 lease 周期。修复直接影响生产滚动升级的中断时长。https://github.com/kubernetes-sigs/karpenter/pull/3490
  - **Karpenter × VPA prediction E2E**(#3447):为基于 VPA 预测做节点 sizing / drift 替换补 E2E,说明 Karpenter 正把 VPA 预测纳入扩缩容决策——与我们 GPU 节点 right-sizing 方向相关,值得持续跟踪。https://github.com/kubernetes-sigs/karpenter/pull/3447
  - 两处性能修复:disruption 控制器不再因 pod 事件做无谓 reconcile(#3418)、`OrderByPrice` 预计算实例价格降 CPU 热点(#3488)。
- **HPA**:新 KEP-6003(sig/autoscaling,10-27 建)——HPA 控制器改用 `AddAfter` + 从 spec 读周期来 requeue,替换 workqueue rate limiter 里按 HPA 存周期的旧做法,属 alpha 实现的设计对齐。https://github.com/kubernetes/enhancements/pull/6477
- **Cluster API**:窗口内无 release。

## API Machinery & Operator 生态

- 三个工具链(controller-runtime / kubebuilder / operator-sdk)窗口内**均无 release**,但 main 分支有方向性信号:
  - **controller-runtime** main 两项破坏性/行为变更预示下个 minor(v0.26):Go 基线升到 **1.27 + k8s.io/\* v0.38.0-alpha.2**(对齐 K8s 1.38,#3624);**metrics 默认输出 OpenMetrics 格式**(行为变更,#3595);另有 cache/informer 同步改事件驱动(#3615)。升级前需评估 Go 1.27 基线与 metrics 格式变化。https://github.com/kubernetes-sigs/controller-runtime/pull/3624
  - **operator-sdk**:手动升 oras-go → 2.6.1 修 **CVE-2026-50151**,但**尚未进入已发布版本**(最新 tag v1.42.3 为 6 月),用 operator-sdk 打包 OLM bundle 的要盯后续发版。https://github.com/operator-framework/operator-sdk/pull/7113
  - **kubebuilder**:修 `create api --ssa` 使 `make manifests` 正确生成 Server-Side Apply 类型并对非法用法明确报错(#6133)。https://github.com/kubernetes-sigs/kubebuilder/pull/6133

## 网络 & 存储(大盘)

### 网络
- **Cilium 1.20.4 / 1.19.10 / 1.18.16(10-23,三线同日带外安全补丁)⚠️**:根因 **CVE-2026-111943**(Go eMudhra CA),升 Go 1.26.10。1.20.4 还顺带修了:阿里云 IPAM 支持 RRSA 凭证、`--policy-cidr-match-mode=nodes` 下通配 CIDR selector 可匹配节点、CiliumEnvoyConfig 只重定向本 namespace Service(回归修正)、NAT46x64 网关 panic、trafficDistribution 下终止中 backend 被误逐出 BPF map。https://github.com/cilium/cilium/releases/tag/v1.20.4
- **Gateway API v1.7.0-rc.3(10-23,预发布,GA 临近)**:`ListenerSet` 新增 **pre-routing listener filters**(GEP-5224);**`TLSRouteMixedMode` 从 Experimental 提升到 Standard channel**;`HTTPRouteRetry.Attempts` 回退为 `*int`、最小值降到 0(可按 rule 关重试);XBackend `endpointSelector.matchLabels` 加 CEL 校验。多租户入口/网关路线图可据此规划。https://github.com/kubernetes-sigs/gateway-api/releases/tag/v1.7.0-rc.3
- **Calico v3.32.3(10-28,patch,无 CVE)**:大量 eBPF 修复(API Server Service 与无关 Service 共享 NAT service ID 致错路由、策略程序被 verifier 拒致节点 not ready、L3 设备重定向 TTL/源地址损坏);**发布 native v3 CRD 的 v1beta1 变体供 K8s 1.34/1.35 用**(这两版不以 v1 提供 MutatingAdmissionPolicy)——基线上移信号;策略引擎按代价最小优先,大策略集 1.6–3.7x 加速。https://github.com/projectcalico/calico/releases/tag/v3.32.3
