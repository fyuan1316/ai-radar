# K8s AI 基础设施周报 2026-08-06

> 覆盖窗口:2026-07-30 ~ 2026-08-06。只看 AI-specific 组件(GPU/加速器、DRA、Kueue/LWS/JobSet/scheduler-plugins),通用集群能力归 [k8s-core](https://github.com/fyuan1316/ai-radar/blob/main/digests/2026-08-06-k8s-core.md)。

## 摘要(3 条以内)

1. **NVIDIA GPU Operator 的 DRA 模式正在成型为一等公民**:`GPUCluster` CR(DRA 栈)与 `ClusterPolicy`(device-plugin 栈)本周被明确设为**互斥、不可共存**;DRA 模式下不再部署 GFD,DCGM exporter 改为直接读 ResourceSlice 把 `(pool, device)` 解析回 GPU UUID 并**默认开启 pod/dra 归因**。这是"device-plugin → DRA"迁移路线在 operator 层落地的关键一周。
2. **LWS 的 DisaggregatedSet(PD 分离原生 API)从 v0.9.0 后续版本开始补齐能力**:slices / 每 slice 角色副本 / 滚动更新 / placement policy / 借 HPA·KEDA 做 External 扩缩,本周主要是文档与命名体系(`<ds>-<slice>-<revision>-<role>`)定型 + SubGroupPolicy 注解传播修复。这是把 vLLM/Ray 那套 prefill/decode 分离搬到 K8s 原生工作负载的方向标。
3. **Kueue 在 v0.19.0 GA(07-22)后进入密集加固期**:公平调度(AFS 准入惩罚门控)、拓扑感知(TAS 弹性扩缩的 leader 保持 / 无资源请求 PodSet 的 flavor 推断)、弹性 workload slice 的优先级变更传播——没有新特性,全是把新 GA 能力的正确性补齐。本窗口 kubernetes/enhancements **无 AI 相关 KEP 合并**。

## GPU / 加速器管理

### NVIDIA GPU Operator — DRA 模式从"可选"走向"默认形态"(重点)
本周 gpu-operator 合入一批 PR,主线是把 DRA(Dynamic Resource Allocation)栈补齐成与传统 device-plugin 栈对等、且默认行为正确的部署形态:

- **两栈互斥**:移除 `nvidia.com/gpu-operator.resource-allocation.mode` 节点标签,node-labeling-controller 不再按该标签决定部署哪套栈;并强制 **`ClusterPolicy`(device-plugin)与 `GPUCluster`(DRA)不能在同一集群共存**,一个集群只跑一套。官方留了话:未来若定好"按节点选栈"的机制会放开。([#2696](https://github.com/NVIDIA/gpu-operator/pull/2696))
- **DRA 模式不再依赖 GFD**:`GPUCluster` 下不部署 GPU Feature Discovery,compute-domain kubelet plugin 通过默认置 `GPU_CLIQUE_LABEL_ENABLED=true` 自己打 clique 节点标签,替代原先 GFD 生成的标签。([#2699](https://github.com/NVIDIA/gpu-operator/pull/2699))
- **DCGM exporter 默认恢复 pod/DRA 归因**:迁到 GPUCluster 后,DCGM 指标此前会静默丢失 `pod/namespace/container/dra_*` 标签(除非手动开 `enablePodLabels`)。原因是 DRA 把分配上报成 `(pool, device)` 而非 UUID,exporter 需带 ServiceAccount token 读节点 `resourceslices` 才能解析回 UUID。本周把 DRA 环境变量、token 挂载、ClusterRole/binding 改为**无条件渲染**,`enablePodLabels/enablePodUID` 只控行为;并删掉已无消费者的 `PodMetadataEnabled` gate。([#2706](https://github.com/NVIDIA/gpu-operator/pull/2706),前置 [#2697](https://github.com/NVIDIA/gpu-operator/pull/2697))
- 其余 DRA 修补:`HOST_ROOT` 环境变量修正 + PassthroughSupport 缺失挂载补齐([#2707](https://github.com/NVIDIA/gpu-operator/pull/2707));OLM bundle 逻辑同步覆盖 dra 镜像([#2692](https://github.com/NVIDIA/gpu-operator/pull/2692));node-labeling-controller 改为 watch 单例 CR 的 create/update([#2704](https://github.com/NVIDIA/gpu-operator/pull/2704))。
- 非 DRA 杂项:vGPU device-manager DaemonSet priorityClassName 修复([#2712](https://github.com/NVIDIA/gpu-operator/pull/2712))、vfio-manager preStop hook 修复([#2711](https://github.com/NVIDIA/gpu-operator/pull/2711))、sandbox-device-plugin bump v0.0.4([#2710](https://github.com/NVIDIA/gpu-operator/pull/2710))、nvidia-fs bump v2.29.4([#2715](https://github.com/NVIDIA/gpu-operator/pull/2715),与 compute-nv-watch 重叠)、rhel-like 发行版 nodeSelector 只用大版本号([#2708](https://github.com/NVIDIA/gpu-operator/pull/2708))。

无新 release(最新仍为 v26.3.3,2026-06-25)。

### NVIDIA k8s-device-plugin
仅一条 grpc 1.82.1→1.83.0 依赖 bump([#1942](https://github.com/NVIDIA/k8s-device-plugin/pull/1942)),无功能变化。最新 release v0.19.3(2026-06-22)。信号:device-plugin 仓已进入维护期,NVIDIA 的增量投入明显转向 DRA 侧。

### node-feature-discovery
Topology updater 从 get+update 改为 **server-side apply** 打补丁,NFD 成为该字段 owner,少一次 get,大规模下降低 kube-apiserver/etcd 的 CPU 压力。([#2564](https://github.com/kubernetes-sigs/node-feature-discovery/pull/2564))最新 release v0.19.0(2026-07-10)。

## 调度 & 资源分配

### Kueue —— v0.19.0 GA 后的加固期(无新特性)
v0.19.0 于 07-22 GA(同日 backport v0.18.4 / v0.17.8),本窗口是围绕 main + release-0.18/0.19 的密集 bugfix/cherry-pick,主题:

- **公平调度(AFS,Admission Fair Sharing)**:AFS 准入惩罚(entry penalty)改为**按准入模式和调度 pass 门控**,避免在不该记账时叠加惩罚。([#13844](https://github.com/kubernetes-sigs/kueue/pull/13844))
- **拓扑感知调度(TAS)**:弹性 workload 扩容时**保持 leader 分配不变**([#13574](https://github.com/kubernetes-sigs/kueue/pull/13574));对"无托管资源请求的分组 PodSet"能推断 flavor([#12562](https://github.com/kubernetes-sigs/kueue/pull/12562));`TASFlavorCache.NodeLabels` 加读锁修数据竞争([#13843](https://github.com/kubernetes-sigs/kueue/pull/13843))。
- **弹性 workload slice**:优先级类(priority-class)变更能应用到兼容的 workload slice([#13780](https://github.com/kubernetes-sigs/kueue/pull/13780));弹性缩容与 failedIndexes 交互补测试([#13722](https://github.com/kubernetes-sigs/kueue/pull/13722))。
- **健壮性**:ProvisioningRequest 创建遇瞬时冲突时重试、不落盘陈旧错误([#13785](https://github.com/kubernetes-sigs/kueue/pull/13785));ClusterQueue 删除后修 LocalQueue status 用量陈旧([#13708](https://github.com/kubernetes-sigs/kueue/pull/13708));watcher goroutine 不再比 owner 活得久([#13705](https://github.com/kubernetes-sigs/kueue/pull/13705));Pod 集成拒绝按 group name 收养非 pod-group 的 Workload([#13014](https://github.com/kubernetes-sigs/kueue/pull/13014))。

## KEP 动向
- 本窗口 `kubernetes/enhancements` **零合并**,无新增或状态变更的 AI/GPU/DRA/scheduling/topology KEP。
- 唯一有实质 KEP 语义的动静在实现侧:NVIDIA 用 `GPUCluster` CR 把 DRA(KEP-4381 系)从 alpha 能力落成 operator 的可部署形态,是判断"DRA 何时可生产用"的一手信号——目前看仍是 operator 自带的独立栈,而非替换 device-plugin 的默认路径。

## 值得跟进
- [ ] **DRA 迁移路线**:GPU Operator 的 `GPUCluster` 与 `ClusterPolicy` 强制互斥,意味着"集群级二选一"。我们产品若要支持 DRA,需想清楚是整集群切换,还是等 NVIDIA 放开"按节点选栈";DCGM 归因依赖读 `resourceslices`,要评估我们多租户 RBAC 下给 exporter 授 ResourceSlice 读权限的合规影响。
- [ ] **LWS DisaggregatedSet**:紧盯 v0.9.0 后续 release,这是 K8s 原生跑 prefill/decode 分离推理的主线,直接对标我们上层推理编排的自研工作负载;关注 placement policy 与 External(HPA/KEDA)扩缩的成熟度。
- [ ] **Kueue TAS/弹性 workload**:v0.19.0 GA 后的这批修复说明"弹性 workload + 拓扑感知"仍在稳定化,若我们排产上生产,建议锁 v0.19 的 patch 版而非 x.0。
- [ ] **NFD server-side apply**:大规模集群 apiserver/etcd 压力优化,若我们自带 NFD fork 可借鉴同样把 topology updater 改成 SSA。
- [ ] enhancements 本周静默,下周重点 grep DRA partitionable/consumable capacity、device taint 相关 KEP 的推进。
